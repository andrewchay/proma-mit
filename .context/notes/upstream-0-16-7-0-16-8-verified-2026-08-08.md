## 三、真正剩下的借鉴价值（按优先级）

1. **xAI/Grok 订阅 OAuth 渠道**（中优先级，功能差异）
   - Gravitas 想对齐 Proma 的多渠道订阅能力可做；成本：新增 provider 适配 + OAuth 授权 + 通用渠道管理已存在，接入难度可控。
   - 但若当前受众用 DeepSeek/OpenAI 为主，收益一般。**列为可选项**。

2. **Todo 草稿自动保存**（中低优先级，UX 泛化）
   - 官方实现范式值得抄：停顿 800ms 防抖自动保存 + 失焦即存 + 关闭面板 flush + "保存中/✓已保存"状态提示 + 不打断输入。
   - 适用场景：Gravitas 任何有长文本编辑且易误关丢失的地方（任务描述编辑、备注框等）。**建议以"编辑器防丢失"通用模式沉淀，而非照搬 planning 绑定。**

3. **Pi 上下文溢出恢复 / Windows 剪贴板主进程**（低优先级，已从分析角度验证必要性低）
   - Gravitas 若非 Windows 主流或 Pi 溢出少见，可暂缓；值得在遇到真实 bug 时对照官方修复查。

## 四、本次可借鉴的实现细节（值得抄进代码的"范式"）

- **模型家族判断**：`CLAUDE_MODEL_PATTERN = /claude[\s._:/-]+(?:(?:opus|sonnet|haiku|fable|mythos)\b|\d+...)/` —— Gravitas 已用 `isClaudeFamilyModel` 覆盖，若未来遇到 `claude-opus-4-8` 系列扩张，可补充 fable/mythos 词表。
- **Vision Relay 安全链路**（最佳实践，Gravitas 已含）：realpath+O_NOFOLLOW 防 TOCTOU、fd 打开后校验 inode、sharp 解码重编码杜绝伪图片外发、系统提示嵌入"图片内指令不可信"、`{answer,observations,limitations}` 受限结构。
- **`@file` 空格编码**：htmlToMarkdown 序列化 encodeURIComponent，发送链路解码还原真实路径给 Agent；展示层复用解码 —— 避免 `@file:(\S+)` 正则被空格截断。

## 五、结论

上一份分析（8-03）的 6 项差距，本次核实后：
- **2 项已完全落地**（64K gate、Vision Relay）
- **1 项部分落地**（@file 引用，需复核拖拽回退链）
- **1 项无此形态**（Todo 草稿，需按长输入编辑场景重新定位）
- **1 项可新增但非刚需**（xAI/Grok 渠道）
- **1 项待真实 bug 触发时再对照**（Windows 剪贴板）

**一句话**：Proma 这两个迭代的"硬改进"（64K 误判、Vision Relay 安全链）Gravitas 已吸收；真正剩余的借鉴空间是 **xAI/Grok 渠道接入**（可选）和 **"编辑器草稿防丢失"UX 模式**（建议做成可复用通用能力）。
