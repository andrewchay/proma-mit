# 微信开放平台第三方平台申请材料（P3-01 准备稿）

> 状态：材料准备稿。提交、资质审核与全网发布验收是外部动作，需要企业主体与人工推进。
> 本文档的目标是让提交材料与产品实现保持一致——申请什么权限，代码里就只实现什么。
> 基准时间：2026-09-17。微信开放平台的具体页面流程可能变化，提交前以官方文档为准。

## 1. 申请前提（需企业侧准备）

| 项 | 说明 | 状态 |
|---|---|---|
| 企业主体 | 开放平台账号需完成企业认证；个体户不可申请第三方平台 | 待确认 |
| 服务号 / 公众号 | 用于第三方平台账号管理的管理员账号 | 待确认 |
| 已备案域名 | 授权事件接收 URL 必须是 https 且域名已 ICP 备案 | 待确认 |
| 服务器固定出口 IP | 换取 component_access_token 需配置 IP 白名单 | 待确认 |
| 数据安全承诺 | 涉及商家公众号数据（用户分析、留言），需隐私政策与安全说明 | 本文 §4 草案 |

## 2. 权限集草案（与产品实现一一对应）

> 原则：只申请代码已实现或第一波即将实现的权限。多申请的权限既是审核风险，也是安全风险。
> 当前产品状态对照：P2-01～P2-09 已实现 direct 直连能力，P3 第一波落地回调与 Token 生命周期。

| 接口权限（平台术语） | 用途 | 产品对应实现 |
|---|---|---|
| 公众号消息与菜单权限集 | 接收 component_verify_ticket、授权事件推送 | P3-02（已实现回调验签/解密/ticket 存储） |
| 网页授权（snsapi_base / snsapi_userinfo） | 商家授权页跳转 | P3-04（待实现） |
| 素材管理 | 代商家上传图片素材 | P2-03（已实现，执行器按 capability gating 启用） |
| 草稿箱 | 代商家创建/管理草稿 | P2-04（已实现） |
| 发布能力（freepublish） | 代商家提交发布与查询状态 | P2-05（已实现，提交≠发布，状态由查询确认） |
| 数据统计（用户/图文） | 商家账号数据分析 | P2-07（已实现，口径分离） |
| 评论（留言）管理 | 留言只读同步 | P2-08（已实现，只读） |
| 客服消息 | 人工审批后的客服回复 | P4-04（未实现，暂不申请） |
| 微信小店/电商类权限 | 未规划 | 不申请 |

明确**不申请**的：群发接口、微信支付相关、广告主接口——产品没有对应能力，申请即违约。

## 3. 与产品描述一致性的自检清单

- [ ] 权限集清单中的每一项都能在代码中找到对应模块与测试（上表第三列）
- [ ] 产品描述（提交给微信审核的应用说明）不承诺「自动发布」「自动回复」——产品实现是**人工审批后受控执行**
- [ ] 提交的授权事件接收 URL 与部署环境一致，且 IP 白名单包含该环境的出口 IP
- [ ] EncodingAESKey 与 Token 的保管方式：仅存于服务端启动配置，不进代码库、不进日志（见 P3-02 实现）
- [ ] 商家授权流程不收集管理员密码（P3-04 设计约束）
- [ ] 隐私政策与 §4 草案一致，特别是「不保存商家管理员密码、Token 加密存储」的表述

## 4. 隐私政策要点（草案）

面向商家授权者的数据说明，需在第三方平台详情页与授权页展示：

1. **收集内容**：商家授权后，平台代为访问公众号的素材、草稿、发布状态、图文/用户统计数据与留言（只读）。
2. **不收集**：商家管理员的微信登录密码（授权走微信官方扫码确认）；留言作者的微信身份信息本地不做画像。
3. **存储方式**：凭据类数据（component_access_token、authorizer_token）加密存储；留言与统计数据按商家（租户）隔离，互不可见。
4. **删除与退出**：商家在微信后台取消授权后，平台立即停止对该公众号的一切调用，并在 X 天内删除其数据（X 由产品定，建议 ≤30 天，需与 P4-12 删除演练对齐）。
5. **人工参与**：一切对外发布与回复动作必须经商家（或其操作者）逐次人工审批；系统不自动外发。

## 5. 全网发布验收须知

全网发布阶段微信会向授权事件接收 URL 自动推送固定测试消息，验收点包括：

1. ticket 接收与 component_access_token 换取（P3-02/P3-03 覆盖）；
2. 授权事件（authorized/unauthorized/updateauthorized）的正确应答（`success` 应答，P3-02 已返回 success）；
3. 消息与菜单事件加解密转发（**当前未实现**，P3 第二波需补：消息转发给授权公众号并回包）；
4. 网页授权域名校验。

⚠️ 待办：验收第 3 点（消息转发）在当前实现范围之外，需要在提交全网发布前完成，否则验收必失败。此事项应记入 P3-09/P3-04 的实施范围。

## 6. 提交流程（人工步骤）

1. 开放平台后台创建「第三方平台」应用，填写基本信息与 §2 权限集；
2. 配置授权事件接收 URL（部署环境确认后）与 Token/EncodingAESKey；
3. 配置 IP 白名单；
4. 提交审核，等待资质与权限集审核；
5. 审核通过后进入「全网发布」验收流程（§5）；
6. 验收通过 → 生产可用，进入 P3-04/P3-10 阶段。
