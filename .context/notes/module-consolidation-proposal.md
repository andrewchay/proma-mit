## 2. 问题诊断

### 2.1 设置 21 个 Tab 平铺 = 最大认知负担

- 低频配置（数据迁移、磁盘管理、操作审计、Proma 教程）与高频配置（模型、外观）平级混排
- 无分组层级，滚动成本高

### 2.2 "自动化/运行"概念 4 个入口并存

| 入口 | 位置 | 内容 |
|---|---|---|
| 自动任务 | 工作模块 | 运行中任务（RunRecord） |
| 定时任务 | 设置 | Proactive Scheduler 管理 |
| 运行记录 | 设置 | Agent/Workflow/定时任务运行历史 |
| 设备控制 | 设置 | Computer Use / AI SDK 诊断 |

同一心智模型（"让机器替我干活 + 看它跑得怎么样"）被拆到 4 处。

### 2.3 "任务"概念 3 处并存

- 项目管理：任务/子任务/看板/我的工作
- 日程管家：右侧任务看板（ScheduleTask）
- 侧边栏工作模块：独立的"任务"占位（孤儿）

### 2.4 工作模块入口与设置功能重叠

- 日程管家（工作模块）↔ 日历同步（设置）——已部分合并（子视图），设置里仍有独立 Tab
- Agent 技能（工作模块按钮）↔ 提示词管理/Chat 工具/Agent 配置（设置）——跳转入口语义不清晰
- 自动任务（工作模块）↔ 定时任务/运行记录（设置）——见 2.2

### 2.5 无"未来模块"框架，PAA 剩余 14 个模块会加剧膨胀

按当前平铺方式逐个接入，设置与工作模块会继续失控。

---

## 3. 合并原则

1. **一个概念只保留一个主入口**（消除重复入口）
2. **按用户目标分层**：日常执行 → 工作模块；配置 → 设置（分组）；低频/专业 → 扩展（折叠）
3. **设置面板按组折叠**：高频展开，低频默认收起
4. **建立模块注册表**：为未来模块（含 PAA 剩余模块）提供统一接入框架，防止再次膨胀

---

## 4. 合并方案（分三层）

### 4.1 设置面板：21 Tab → 5 组（推荐优先实施，UI 改动小）

左侧导航改为「分组 + 可折叠」，保留全部功能但层次化：

```
设置
├─ 基础配置      通用设置 · 外观设置 · 快捷键 · 语音输入 · 关于/更新
├─ 模型与智能体  模型配置 · Agent 配置 · 视觉助手 · Chat 工具 · 提示词管理 · 扩展
├─ 连接与同步    远程连接 · 代理设置 · 日历同步
├─ 自动化与运行  定时任务 · 运行记录 · 设备控制
└─ 系统与隐私    磁盘管理 · 数据迁移 · 操作审计 · Proma 教程
```

可选的进一步收敛（低优先）：
- 「Proma 教程」并入「关于/更新」（都属"学习/信息"）
- 「设备控制」并入「Agent 配置」的诊断区（都是运行时能力诊断）

### 4.2 工作模块：4 → 3（合并"任务"占位）

| 工作模块 | 内容 | 动作 |
|---|---|---|
| 日程管家 | ScheduleView + 日历同步子视图 | 保留（已合并） |
| 项目管理 | ProjectView（项目/任务/看板/会议/风险） | 保留 |
| **自动化** | 自动任务运行中心 + 定时任务管理 + 运行记录 | **合并 3 处**（工作模块做"自动化"聚合；设置内不再重复 3 个 Tab，改为单入口或移到工作模块） |
| 任务 | 占位 | **移除**：任务概念归入项目管理（"我的工作"）与日程管家（任务看板），不再单设入口 |

> 说明：`tasks` 占位视图与 ActiveView 类型一并删除；"我的工作"是项目模块内已有 Tab，可在项目管理首屏强化。

### 4.3 模块注册表框架（面向未来，防止再次膨胀）

参照 PAA `paa-module-registry.ts` 建立统一模块注册表：

```
模块注册表条目：{ id, label, icon, group, core: boolean, lazyPath }
```

- **core 模块（≤4-5 个）**：直接显示在工作模块。当前：日程管家、项目管理、自动化；（候选）知识库
- **扩展模块（低频/专业）**：收进工作模块底部「更多模块」折叠分组，或仅出现在设置「模块管理」
- **PAA 剩余模块合并建议（若后续迁移）**：
  - 知识库（Knowledge）→ core 候选（与记忆/检索强相关）
  - 分析引擎 + 洞察中心 + 复盘记录 → 合并为「分析」一个模块（内部 tab）
  - 投资四件套（trading/broker/riskMonitor/backtest）→ 合并为「投资」一个模块（内部 tab）
  - 学术/研究/开发 → 合并为「研究」一个模块（内部 tab）
  - 邮箱 → 归入个人生产力；家庭 → 扩展分组
