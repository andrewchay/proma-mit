# Gravitas Dev / Stable 隔离审计与收尾计划

## 目标
在现有 Dev/Stable 隔离实现基础上，复核近期风险审计提到的缺口；仅对确认的缺口做最小修复与 BDD 测试。避免写入或迁移正式数据，避免退出当前生产宿主，不提交、不推送、不发布。

## 已知状态
- 仓库已有独立 appId、显示名、协议、配置根、userData、Dev 构建输出及更新渠道门禁。
- 工作树已有大量未提交改动，包括 Dev/Stable 隔离本身及其他功能；所有现有改动都属于用户工作，必须保留，修改前对目标文件核对现状。
- 当前分支 main 比 origin/main ahead 1；本任务不提交、不推送。
- 最近审计提醒：模块导入触发调度、Brief 固定端口监听、备份导入保留外部工作区路径，以及退出清理和 CI 产物门禁。

## 步骤
1. [x] 只读审阅近期 Dev/Stable 审计笔记、启动及退出路径、Brief/Companion 服务、备份导入映射、CI release workflow，确定哪些问题仍存在。
2. [x] 对确认缺口做最小安全修复与 BDD 测试；复用 app-channel / config-paths 既有抽象。
3. [x] 运行定向测试、渠道门禁、相关 lint/typecheck 与文档事实检查；未运行全量测试/lint。
4. [x] 检查 git diff，确认保留既有工作树改动；真机并存、升级恢复仍待验收。

## 安全边界
- 不读取、复制、删除或迁移 `~/.gravitas` 正式数据。
- 不启动会触发生产写入的应用操作，不退出当前 Gravitas 生产宿主。
- 不运行安装、发布、上传、推送或提交命令。
- 用户既有工作树改动视为不可覆盖；仅在理解现有 diff 后精确修改。

## 验收标准
- 报告近期审计各项问题的现状及证据。
- 若修改代码，新增/更新测试验证 Dev 与 Stable 行为差异。
- 相关测试和静态检查通过，或明确列出失败及归属。
- 生产数据和既有未提交改动保持不变。
