# S8 真实项目观察 · 执行手册

- 目的：用真实数据检验"观察—判断—提醒"是否值得保留，并据此决定是否进入第四批（受控行动）。
- 状态：**未执行**。本机没有可用的真实 Provider、搜索凭据与带外部变化的真实项目，
  且真实扫描会产生第三方费用，必须由你确认后执行。
- 进入第四批的硬条件：本手册的观察结果已产出并被你认可。没有这份结果，不得设计第四批。

## 1. 前置条件（缺一项则不开始）

1. 已启用至少一个可用 AI 渠道（`设置 → 渠道`），`modelId` 会写进每条观察的 `evaluation.modelId`。
2. 已配置 WebSearch 凭据（Tavily 或秘塔）。
3. 选一个有真实目标、且外部环境确实在变化中的项目（例如依赖的框架、平台规则、供应商政策）。
   纯内部项目不适合，观察不到东西是选样问题，不是功能问题。
4. 项目已建立 Owner 目标与（可选）管理委托。没有委托时观察只落账本、不进对话。
5. 你明确同意产生这些扫描费用。

## 2. 执行步骤

```text
第 0 天：项目 → 外网扫描 → 填 2–4 个具体主题（不要写"行业动态"这种泛词）→ 立即扫描 1 次
第 1–7 天：每天 1 次（可手动"立即扫描"，也可开每日自动）
第 1、3、7 天：各记录一次「人工对照」——当天你实际关心的外部变化，与系统是否命中
第 8 天：用汇总函数出数字，填下表，写下结论
```

主题写法要求：能被一条搜索命中具体页面，例如 `Next.js 15 破坏性变更`、`微信小程序审核规则更新`。
写 "AI 行业趋势" 这类词，得到的必然是无法判断相关性的泛泛内容。

## 3. 记录表（每次扫描一行）

| 日期 | 新来源数 | 判定 | 值得看? (是/否) | 发布时间确认 | 我做了什么 | 备注 |
| --- | ---: | --- | --- | --- | --- | --- |
| 11-02 | | | | | | |
| 11-03 | | | | | | |
| … | | | | | | |

判定列只能是 `record_only` / `attention` / `decision_required` / `insufficient_evidence` / `duplicate`。

## 4. 自动可得的数字

`summarizeWebObservationQuality(projectId, since)`（`project-web-observation-metrics.ts`）输出：

| 指标 | 用途 | 判断参考 |
| --- | --- | --- |
| `observations` | 观察条数 | 7 次扫描应 ≥7 条（含 `insufficient_evidence`） |
| `byJudgment` | 五态分布 | `attention` 连续 3 天以上 → 可能有噪音 |
| `duplicateRate` | 重复判定占比 | 持续 >0.5 → 主题太宽或来源太稳定，应收窄主题 |
| `insufficientRate` | 证据不足占比 | 持续 >0.3 → 模型或搜索质量有问题，先修再谈第四批 |
| `factsWithoutPublishedAt / factsTotal` | 发布时间可靠性 | 占比高 → 时间判断只能当背景，不要采信"新变化" |
| `truncatedObservations` | 上下文被截断次数 | >0 → 主题或来源太多，需收敛输入 |
| `feedback` | 你的反馈分布 | `irrelevant` 集中 → 主题或判据需要调整 |

拉取方式（在应用主进程侧执行，或写一次性脚本调用该函数）：

```ts
const { summarizeWebObservationQuality } = await import('./project-web-observation-metrics')
console.log(summarizeWebObservationQuality(projectId, Date.now() - 7 * 24 * 60 * 60 * 1000))
```

## 5. 需要人工判断的四件事（无法从数字得出）

1. **遗漏**：对照第 1/3/7 天你实际关心的变化，系统漏了几条？漏的是搜索没搜到，还是判断判成无关？
2. **事实准确性**：卡片里的事实引文是否与原文一致？有没有把推断写成事实？
3. **时间准确性**：被判为"本期变化"的内容，发布时间是否真的在覆盖区间内？
4. **提醒成本**：7 天里打扰了你几次？每次你花了多少时间处理？值不值？

## 7. 已知限制（写结论时必须带上）

- 扫描费用**没有**写入 Owner 委托账本，目前只有只读门禁（Owner 额度用尽时跳过）。见计划文档 S4 的"未闭环"。
- 观察判断使用的模型是"第一个启用渠道"，不是 Owner 配置的模型（仓库缺项目级 Owner 模型访问器）。
- 观察卡片尚无浏览器用例；无数据时回退为对话内摘要文本。
- `same_event`（多 URL 同一事件）由模型判断，程序层不做语义归并。
