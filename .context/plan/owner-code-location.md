# AI Project Owner：自动定位真实代码实施计划

## 目标
解除 AO-A02 代码任务真实文件定位阻塞：用户只给任务目标，系统从已授权项目工作区中只读检索相关代码，向单次Owner规划请求提供可追溯证据；不要求用户预先填写文件路径。

## 基线
以用户确认的 AO-02 提交 `4aeacb89` 为基线，在独立新分支/worktree 实施。先检查分支是否仍是该提交的后代及工作树干净，再创建分支；不得改写既有worktree或混入AO-07。

## 阶段
1. **只读源码核验**：追踪 Goal → planning context/source snapshot → admission → SDK 单请求 → Run/Plan proposal；调查现有项目工作区绑定、文件读取/检索、development安全路径规则及测试夹具。记录准确函数/文件和当前阻塞。
2. **安全契约定界**：优先本地确定性只读检索，不开放规划Runtime tools或第二次模型调用。仅使用当前项目显式绑定、已获准的研发工作区；明确是否要新增独立“规划资料授权/准备”确认，未获授权不得读仓库正文或发送片段。目标范围外、无绑定、超限、symlink逃逸、敏感资料均拒绝或报告未定位。不得将规划读取授权解释为执行/写入权限。
3. **用户审批最小设计**：定义候选排序、路径与行号证据、内容截断/字节和文件数上限、秘密过滤、忽略目录、错误/无结果表现；检索结果和索引/仓库快照指纹绑定Goal主体与来源版本，在规划执行前重验漂移。无可靠证据时模型必须标记未定位，不得虚构路径。
4. **实现BDD**：新分支先写失败测试，再实施最小变更。覆盖目标到真实文件定位、项目/任务隔离、未授权零读取/零请求、跨项目工作区拒绝、路径规范化与symlink逃逸、秘密/大文件排除、限额、零命中/多候选、仓库变更导致stale、模型只能引用候选证据且不能伪造工具事实。测试用临时仓库和fake transport。
5. **回归与交付**：执行定向测试、全workspace typecheck/lint、全量测试、docs检查和完整build（按仓库脚本）；检查diff和安全边界。更新Owner capability audit/ledger，明确工程切片与用户/真实Provider验收边界。不得真实Provider调用、安装、push或合并，除非另行授权。

## 不在本次范围
AO-07整合；通用Agent工具授权；任意文件/全盘搜索；自动代码修改、执行、业务任务派发；真实付费模型试跑；发布/安装。

## 验收
- 给出类似“修复负数量报价，保留正常行为”的目标，不提供文件路径，系统能在显式绑定仓库中返回真实候选文件和可核查片段/行范围。
- 任何资料未授权或来源过期时，仓库正文不进入模型请求；无文件路径猜测冒充定位。
- 限额、项目隔离、秘密路径、symlink、stale均有确定性负向测试。
- 保持Owner规划单请求、零工具、费用准入、现有授权与执行隔离不变。
- 完成与未完成证据分开记录；fake-only测试不宣称真实Provider或产品端到端验收。
