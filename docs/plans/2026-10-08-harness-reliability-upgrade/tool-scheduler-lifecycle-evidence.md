# E04 第二十一批：取消/错误/重启矩阵与重试策略证据

> 2026-10-09 22:10 GMT+8。基线 5c39c890。

## 实现

- **重试策略（`runGuardedToolCall` 新增 `retry` 参数）**：
  - 硬规则：仅共享锁（幂等读）调用可按策略重试；含写或 unknown 的调用（外部副作用、不可回放）绝不自动重放。
  - 取消永不重试；默认 `shouldRetry` 排除 AbortError；默认 `maxAttempts=1`（不重试）。
- **禁用开关（`setToolSchedulerDisabled`）**：禁用后退化为全串行（并发 1），**锁仍持有**——硬底线：禁用只牺牲并行度，不放弃冲突串行化。恢复后并行恢复。
- **关键修复（服务测试暴露的缺陷）**：`running` 计数器原为每个 `schedule()` 批次私有，跨批次并发上限与禁用退化失效。改为实例级计数器；禁用测试在修复前恰好表现为并行通过、复现此缺陷。

## 取消语义（既定）

- 排队中的调用：abort → 标记 cancelled，不派发。
- 运行中的调用：**不打断**（工具自身超时/取消负责）；abort 信号仍传给工具上下文。

## 限制

- 重试没有退避/抖动（当前为立即重试）；没有重试指标独立计数（dispatched 按尝试次数计）。
- 运行中调用不被打断：慢工具只能等自身超时。与 E05 相同，锁等待无超时。
- 禁用开关目前是进程内开关，未做持久化设置/UI。
