# E02 第十九批子契约：进程内工具调度器

> 2026-10-09 18:00 GMT+8。只实现调度模块与测试，不接入生产执行路径（E05），无跨进程锁。

## 输入与锁模型

- 输入为一组已解析的调用 `{id, tool（实际注册实例）, input, ctx}`；结果保持输入顺序返回。
- 资源解析复用 E01/E02：实际实例 effects + `resolveRegisteredToolResources` 得到 canonicalPath/mode/coverage。
  - 读调用：对 canonicalPath 加共享锁。
  - 写调用：对全部 coveredPaths（含 Write 的祖先目录）加排他锁；同一调用含写则所有键排他（保守）。
  - unknown（MCP、Bash、资源解析失败）：全局排他键，互相串行。
- 键即真实路径字符串相等；不做目录树包含推断（读目录 vs 写子文件不检测，记入限制）。
- 加锁顺序：每调用按键排序后按序获取、逆序释放——全局定序避免死锁。

## 调度

- 并发上限默认 4；跳过队首阻塞：从队首扫描，第一个全部锁可立即获取的调用先执行（读-读真正并行；被写阻塞时后续无关调用可越过）。
- 同键写保持提交顺序（FIFO 公平）。
- 取消：调度器 abort 后不再派发；执行中调用的 ctx 信号由调用方负责。
- 错误：调用失败释放其锁，其余调用继续；不重试（E04）。

## 边界

锁是进程内逻辑锁：不防跨进程/跨会话竞争，不消除 TOCTOU。不宣称性能收益；不以墙钟噪声断言。E02 整体、HR07–HR09 与 G2 仍未通过；接入生产与跨会话锁域在 E05。
