# E02 第十九批：进程内工具调度器证据

> 2026-10-09 18:10 GMT+8。基线 61cb3fba。仅调度模块，未接入生产执行（E05）。

## 实现（tool-scheduler.ts）

- `planLockSpec`：实际注册实例 → effects → 资源观察。读=canonicalPath 共享锁；写=全部 coveredPaths（含 Write 祖先目录）排他；含写调用全键排他（保守）；unknown/解析失败=全局排他键。
- 调度：并发上限（默认 4）；从队首扫描、第一个全部锁空闲的调用立即派发（跳过队首阻塞，读-读真并行、无关调用可越过被写阻塞的队首）；同键写保持提交顺序。
- 死锁规避：只在“全部锁空闲”时派发，加锁同步完成、逆序释放——不存在持有锁等待另一把锁的结构，无需等待队列（初版等待队列实现存在派发竞争，已重写）。
- abort：不再派发，未开始调用标记 cancelled；错误释放锁、其余继续；结果保持输入顺序；不重试（E04）。

## 测试（10 例）

锁规约（共享/排他/祖先覆盖/unknown/符号链接别名同一键）；同文件写串行保序 + 读-读并行；读写互斥双向；越过队首与目录祖先冲突串行；unknown 全局串行；并发上限；循环批次 3 秒看门狗内完成（不死锁）；失败释放锁；abort 不执行未派发调用。

过程修正（如实记录）：初版异步加锁与 canAcquire 存在竞争（读-读测试暴露）；abort 分支未清队列导致挂起；两处测试夹具问题（对不存在目标 realpathSync、读不存在的文件被判 unknown）。全仓首跑出现 1 个无关偶发超时（project-task-workspace-update，单独 253ms 通过，重跑全仓 0 失败）。
