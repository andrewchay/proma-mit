# 设计系统上下文的缺项与刷新

声明需要设计系统的 Skill 在工作区没有可用 `DESIGN.md` 时，会把缺项提示注入设计上下文，要求执行者告知用户且不声称品牌合规。此提示经现有上下文组合器供 Agent Runtime 使用；它不构成独立的品牌合规检查或界面告警。

临时工作区测试验证同一会话再次读取 Skill 时重新读取更新后的 `DESIGN.md` 与 `tokens.css`，不会复用旧品牌正文；自动化测试未覆盖真实 Provider 的遵循情况或企业品牌资产审批。

## 设计成果选区与反馈

Owner 交付卡可在成果正文选择最多 300 字，或在隔离的 HTML 静态预览中点击含文字的元素，明确选择将片段带入 Owner 修改意见。意见复用已有消息引用，绑定消息 ID、成果 hash 和步骤；选中本身不会发送消息、修改成果或启动执行。

静态预览在 opaque origin 的 sandbox iframe 运行专用选区脚本；预览副本删除成果脚本、嵌套 frame、base 及 http-equiv 元数据，以 CSP 禁止成果脚本与外部资源。宿主只接受当前 iframe、当前随机版本令牌和有限字段的消息，选区内容仍当作不可信文本显示，需用户主动确认使用。浏览器测试覆盖成果脚本不运行、外部资源被拒绝、点击选区与伪造消息；尚未证明全部复杂 HTML、动态交互、打包 Electron 或真实 Provider 场景。下载的原始 HTML 保持原样，用户在浏览器打开时其脚本行为由浏览器环境决定。

选区现已支持图片、SVG 和 canvas：引用显示无障碍描述或“无文字描述”，附带有限层级的预览 DOM 位置供人工定位。这个位置是提示，不保证唯一或能稳定映射到源文件；不会上传图片、读取外部资源，也不会自动修改元素。

## 设计任务草稿

项目 Owner 对话提供网页、报告、幻灯片和海报的设计任务草稿，可填写目标与可选品牌或风格参考；添加时保留已有对话内容，由用户检查后主动发送。此入口不安装品牌资源、不覆盖工作区文件，也不声称设计已符合所选品牌；缺失资源时要求明确说明。浏览器测试覆盖类型、风格、保留已有草稿及不自动发送，尚未验证真实 Provider 生成或品牌资源选择与版本管理。

## 品牌参考目录

设计任务草稿可从内置 OpenDesign 索引选择 152 个品牌/设计系统名称，或补充自定义风格要求；选择后只加入待发送的文本草稿，不下载、安装或激活设计规范。目录不含品牌图形资产，来源及 Apache-2.0 许可记录在生成文件内；可执行 `bun scripts/generate-design-catalog.ts` 从已随包提供的索引重新生成。测试核对生成目录与来源一致，并在浏览器验证选择及不自动发送。品牌资源的实际获取、版本锁定和审批仍待完成。


## 本地设计参考预览

设计任务草稿选择品牌后可以只读查看随应用打包的 DESIGN.md 与 tokens.css；内容来自 OpenDesign 固定版本的整理资料，不代表品牌官方授权。首次选择时按需加载，切换时丢弃过期加载结果。查看不会写入工作区、自动发送或注入 Agent，品牌合规、企业审批与真实 Provider 效果仍需另行验证。可通过 `bun scripts/generate-design-reference-bundle.ts <OpenDesign 仓库路径>` 从同版本且相关文件无修改的检出重建；包中附带 Apache-2.0 许可证。

设计参考支持用户选中说明或令牌中的片段（最多 1600 字），可编辑后加入对话草稿，附来源版本与“非完整规范”标记；切换品牌清除已选片段。用户需检查草稿并主动发送，不能据此宣称完整规范已注入或品牌合规。浏览器测试覆盖选中引用、切换品牌及不自动发送。

本地参考按目录顺序拆分为四个固定版本资源包；首次选择只加载对应包。测试核对每个目录条目落在正确包内，并在浏览器中跨包切换；这不是逐品牌独立下载，构建产物每包约 0.49–0.85 MB。

用户可分别下载所选品牌的完整设计说明和 CSS 令牌原文，保存文件名带品牌前缀，避免与现有文件混淆；如需激活，需由用户自行审阅并决定是否以 `DESIGN.md` / `tokens.css` 放入工作区根目录。浏览器测试核对下载文件名与内容；PR #106 另以实际打包 Electron 验证下载文件名与内容。品牌授权、真实 Provider 对完整规范的遵循和人工使用体验仍未验收。

### Pi Runtime 安装规范注入

补充跨 Runtime 回归时发现，Pi 的 Skill 展开器虽接收 Owner `workspaceSlug`，却没有把它传给已安装设计系统解析器；Owner 会话 cwd 无本地 `DESIGN.md` 时，Pi 误报资源缺失。现在将工作区身份传入共享解析器，隔离测试经 Pi 的 `preparePromptWithPromaSkills` 验证已安装正文、来源版本和 tokens.css 注入。该测试验证本地 prompt 组装，不代表真实 Pi Provider 遵循或用户交付验收。

Claude SDK 的系统提示词构建也新增了隔离回归：在 Owner 工作区安装固定版本规范并启用声明 `od.design_system.requires` 的 Skill 后，完整 system prompt 包含安装正文、来源版本及 tokens.css。此项只验证本地 prompt 组装，不代表 Claude Provider 遵循或业务验收；三条 Runtime 的实际 Provider 表现仍需分别验证。

### Owner 工作区安装与受控注入

Owner 可预览当前绑定的执行工作区及 OpenDesign 参考版本；用户二次确认后，仅在该工作区共享目录安装 `DESIGN.md` 与 `tokens.css`。若目标、项目根目录存在同名文件、安装目录或符号链接冲突，安装拒绝覆盖。安装记录作为独立元数据保存 OpenDesign 版本、来源、项目/工作区绑定、用户确认身份与两份文件的 SHA-256；上下文读取时重新校验摘要，损坏或不完整时不注入。安装确认同时绑定预览时的 Owner 工作区修订、工作区 ID 和 OpenDesign 版本，期间任一变化都要求重新预览。

仅声明 `od.design_system.requires: true` 的 Skill 会获取这份共享安装上下文；若当前执行目录已有本地设计说明或令牌，则保留其优先级。设计说明和令牌作为同一份用户选定的完整参考注入，不意味着模型一定遵守，也不构成品牌授权或合规审核。自动化测试覆盖安装预览、用户确认、冲突拒绝、绑定/资源版本变化、摘要校验及 Owner 工作区回退注入；PR #106 的实际打包 smoke 进一步覆盖 Owner 安装界面/IPC、下载和冲突保护。真实人工操作验收、Provider 遵循和品牌审核仍未完成。

## macOS 测试包检查

在独立工作树以提交 `a35ce85b` 构建未签名 arm64 Owner 测试包；检查 app.asar 中的四个 OpenDesign 资源分片及包内 Apache-2.0 许可证均存在。直接启动测试包，进程存活 10 秒并创建独立的 `Gravitas Owner Test 0.13.406` 配置目录，然后结束本次测试进程。该检查未验证包内下载交互或真实 Provider。打包器提示缺少 node-pty 的 spawn-helper 源文件；启动成功不证明内置终端可用，需另行验证终端及正式签名分发。

### Owner 安装资源路径补齐

检查当前 Owner 安装服务后发现：参考分片虽进入 renderer 的 `app.asar`，但主进程安装服务从 Electron `process.resourcesPath` 读取资源，之前 electron-builder 只复制许可证，导致打包应用无法安装。0.13.515 将目录索引及四个参考 JSON 与许可证一并复制到 `Contents/Resources/opendesign/`，安装服务优先从该目录读取，并保留开发资源回退。定向测试覆盖打包资源目录的读取；未签名 macOS arm64 构建产物中已核实上述六个文件齐全。此证据不包含安装 UI 手动操作、真实 Provider 遵循、品牌授权审核或签名发布验收。

### 打包 Owner 安装服务烟测（PR #104，2026-11-01）

`package-design-smoke` 在实际打包应用启动后，以临时配置目录和临时 Owner 工作区运行安装服务；绑定和 Owner 身份使用烟测夹具，参考内容则由应用实际 `process.resourcesPath/opendesign` 资源读取。烟测执行预览、显式确认安装、读回 DESIGN.md/tokens.css 并精确比对内容、校验来源版本，再确认重复安装被报告为冲突。PR #104 的 macOS arm64、Windows x64、Linux x64 package smoke 与 quality/executor 共五项 CI 全部通过。该证据覆盖实际包资源读取和安装服务闭环，不覆盖 Owner 界面人工点击、生产 Owner 绑定、真实 Provider、品牌授权或客户验收。

### 打包 Owner 安装界面 smoke（PR #106）

在 #104 服务烟测上增加独立 Owner 界面流程：隔离包配置下建立临时项目、工作区和绑定，打开 Owner 对话的设计任务卡，预览绑定工作区、点击二次确认并通过实际 IPC 安装；随后读回实际包内 Stripe 参考内容，并在第二次预览时核对冲突提示、确认按钮消失且原内容不变。员工渠道只作为绑定夹具，从不发起 Provider 请求。PR #106 的 quality、executor 和 macOS arm64/Windows x64/Linux x64 package smoke 均通过；这只代表打包自动化覆盖了 UI/IPC/服务链，不等同于人工操作验收或真实 Provider 品牌遵循。

## 工艺参考缺项提示

Skill 显式要求的 craft 章节若目录不存在、文件缺失、为空或无法读取，组合上下文会列出缺项并要求执行者说明，不声称遵循了缺失内容；可用章节仍正常注入。定向测试覆盖全部缺失、部分缺失、完整资料及 ReadSkill 接线；该提示不证明真实 Provider 会遵守，也不是独立品牌合规审核，其他 Runtime 和打包应用仍需各自验收。
