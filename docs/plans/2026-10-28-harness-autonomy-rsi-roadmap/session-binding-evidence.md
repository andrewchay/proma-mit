# AI SDK 工具上下文绑定：局部证据

工具集创建时拷贝会话 ID、工作目录及工作区等上下文字段，后续修改传入的原状态对象不会改变该工具集的身份。执行时传给工具及调度器的上下文对象被冻结；Owner 和隔离写入标记在工具集创建时固定，并在用量结算等待后、审批返回后及调度器实际执行前复核，变化则失败关闭。权限模式仍可通过现有用户交互调整。

BDD 测试覆盖原状态中的会话 ID 与目录被改写、Owner 标记变化、审批等待期间标记变化、隔离写入标记变化；现有 AI SDK 工具、会话门禁与调度器定向回归通过。标记发生变化不会自动终止已经执行的工具。

这是 AI SDK 路径内的状态漂移防护，不是不可伪造的身份能力：工具集创建时的上下文来源仍须可信；直接调用底层工具、其他 Runtime、子 Agent 的身份继承和进程内不受信代码仍需覆盖。冻结为浅冻结，不代表所有引用对象不可变；交互式工具等待中的撤权、跨进程隔离及真实 Provider/打包应用验收仍未完成。

## 活动会话身份绑定

AI SDK 适配器在创建活动会话时将会话对象与会话 ID、规范化工作目录绑定；同一对象不能重新绑定其他身份。工具集执行时必须匹配该绑定，未绑定或不匹配会在工具执行前失败关闭，并在等待、审批与调度后重查。测试覆盖不同会话、不同目录、重复绑定、未绑定拒绝及真实受控项目任务回归。该关联存于主进程内 WeakMap，不是进程隔离或密码学凭据；进程内受信代码仍可调用绑定入口，其他 Runtime、直接调用底层工具及子 Agent 身份继承仍待单独验证。

会话正常结束、直接停止或适配器释放时撤销该身份；撤销后的对象不能再次绑定，旧工具在派发前被拒绝。定向测试覆盖撤销后工具调用、重新绑定，以及 mock Provider 的适配器正常结束后调用旧工具；这不保证已经派发的外部动作停止。

旧运行停止后，同 ID 的新运行可能已启动而旧运行才结束；AI SDK 适配器仅在活动表仍指向旧对象时删除它。延迟流测试先复现旧运行清理导致新运行无法停止，再验证修复。适配器入口同时拒绝同 ID 活动运行的并发启动，测试覆盖拒绝后原运行仍可停止。

## Pi 工具桥上下文快照

Pi 工具桥在创建时复制并冻结上下文，普通工具与交互工具的调用上下文也被冻结；适配器构造上下文时先合并允许的扩展字段，再写入会话 ID、工作目录、权限模式和 Owner 标记。测试覆盖创建工具集后来源对象的会话与目录被改写，工具仍接收初始值；Pi 桥和适配器定向回归通过。这只防止上下文对象漂移，未建立不可伪造的 Pi 会话来源，也不覆盖运行中的撤权与其他 Runtime。

独立全仓回归发现工具加载测试直接构造 runtime 会话，未经过适配器绑定而被新门禁拒绝；生产路径由适配器绑定。测试夹具现按同一契约绑定，工具加载、AI SDK 核心和受控项目任务定向回归通过；旧提交的全仓运行包含该失败，不计为通过。

## Provider-Agnostic 工具批次上下文

Provider-Agnostic 路径在每个工具批次开始时复制并冻结上下文；异步权限检查期间来源对象被改写时，工具及 Owner 禁止检查继续使用初始会话与工作目录。定向测试先复现漂移后验证修复。该路径仍依赖工具批次创建时的可信上下文，且 Owner 业务会话原有拒绝规则不变；这不是跨进程身份能力或完整撤权实现。

## 会话与工具级停止信号

AI SDK 工具调用同时监听绑定会话和 SDK 工具级停止信号，任一取消即停止后续派发；用量等待、审批返回和调度执行前复核取消状态。计划审批与用户问答等待结束后也重新核对停止与会话标记，取消后不切换权限或返回回答。定向测试覆盖工具级 signal 未取消但会话已停止、审批中停止、计划审批中停止与问答中停止。该切片不证明已派发的外部动作已回滚或退出；未知结果仍需对账。

Pi 工具桥也合并会话与工具级停止信号，并在审批、问答及调度等待后复核；适配器直接停止或释放会话时会取消关联工具信号。测试覆盖独立工具 signal 未取消、审批中停止，以及直接停止或正常结束后旧工具调用。软中断与已执行外部动作的实际退出仍需分别验证。

Pi 的同 ID 重启也使用活动对象校验：旧运行结束和旧调用方的迟到取消不会清除或停止新运行。延迟 prompt 的模拟测试覆盖两种情况；这不是进程级隔离，也不代替入口并发守卫。

Pi 在异步初始化前占用会话 ID，拒绝同 ID 初始化或活动运行并发；初始化中停止会取消该启动并在退出前保留占用，防止旧启动覆盖新会话。模拟测试覆盖初始化并发、活动并发和初始化中停止后不发 Provider 请求；已完成会话的重新启动仍保留。它不证明外部进程或已派发动作退出。

Pi 普通会话创建的子代理入口在实际委派时重查权威受控状态；若创建后会话转为受控则拒绝。测试用真实项目存储复现状态变化并验证未调用委派回调；其他 Runtime 和已派发的子代理仍需分别检查。

AI SDK 的旧子代理入口也在实际委派时重查受控会话与 Pilot 预算；真实项目存储测试分别覆盖运行开始后转为受控及出现 Pilot 预算，并确认未调用委派回调。已派发子代理的退出仍未验证。

Provider-Agnostic 在异步模型能力读取前后检查调用方停止信号，并在每轮派发模型请求前复核内部信号。定向测试复现父级信号已取消时仍进入模型调用，修复后未发起调用；已派发的请求与外部动作的退出仍需独立确认。
