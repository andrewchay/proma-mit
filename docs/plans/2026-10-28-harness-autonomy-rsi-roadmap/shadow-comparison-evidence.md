# 影子对比与可比性判定：局部证据

> 2026-10-30 更新：scoreboard 评测未保存可信基准与评分规则来源，适配器现一律返回不可比和资源未核验；下文原切片中 scoreboard 可比的描述是历史行为，已被本更新替代。纯 `compareShadowRuns` 仍供调用方在有可信输入时使用，并不验证输入来源。

日期：2026-10-29；范围仅"两侧已落盘评测结果的可比性判定、差值报告与成本/延迟门禁"，不含影子流量采集、Provider 账单核对、统计显著性、UI 呈现与真实人工验收。

## 缺口

RSI 路线剩余的"影子对比"此前没有代码：`self-evolver` 内部虽然有基线与候选的接受/回滚判断（`completeCaseScore` 要求训练集与 held-out case 完整），但那是**单轮优化闭环内部**的决策，不是"两个已落盘版本之间的对比报告"。缺少的是：给定两条历史评测，能否比较、差多少、在什么情况下必须拒绝下结论。

## 本次改动

新增 `eval/shadow-comparison.ts`（纯函数，无副作用、不落盘、不激活能力）：

- `compareShadowRuns(baseline, candidate)`：
  - **可比前提**：基准版本、rubric 版本一致；两侧 case 集合完全一致；单侧内部无重复 case；每个 case 两侧都有 `0..1` 的有限分数。
  - **不可比即拒绝结论**：任一前提不满足时 `comparable=false`、`verdict='inconclusive'`、`meanDelta=null`，并在 `reasons` 里逐条写明（版本不同、缺哪个 case、多哪个 case、哪个 case 没分）。
  - **缺分不按 0 计**：只有分数的 case 保留在明细里供人工查看，但不参与均值与结论。
  - **判定阈值**：均值差绝对值小于 `deltaThreshold`（默认 0.02，可配置）判为 `no_difference`，避免把噪声当提升。
- `describeShadowComparison`：一句话结论；不可比时明写"不可比，不下结论 + 原因"，与"无显著差异"严格区分。
- `shadowRunFromEvaluation` / `compareScoreboardEvaluations`：把 scoreboard 的 0..100 百分制评测转换为 0..1 并复用同一套判定；越界或非有限分数按缺分处理（不裁剪）；`costUsd`/`durationMs` 一并透传。
- **成本与延迟（`resources`）**：给出两侧成本、成本差额、成本与耗时增幅，并按可配置门禁判定：
  - 未配置门禁 → `gate='pass'`，只报告变化比例。
  - 配置了 `maxCostIncreaseRatio` / `maxLatencyIncreaseRatio` 且超限 → `cost_exceeded` / `latency_exceeded`，写明实际增幅与允许值。
  - 配置了门禁但数据缺失，或基线为 0 导致比例无法计算 → `gate='unverified'`，**不当作通过**。
  - 分数不可比 → 资源评估一并不做，`gate='unverified'`。
  - 门禁判定不篡改分数结论：分数仍是 `candidate_better` 时，资源门禁可以同时是 `cost_exceeded`，两者并列呈现。

## 证据

`shadow-comparison.test.ts`（27 项）：

| 场景 | 断言 |
| --- | --- |
| 版本与 case 一致、分数齐全 | `comparable=true`、均值与差值正确、改善/持平计数正确、`candidate_better` |
| 候选明显下降 | `candidate_worse`、退步计数正确 |
| 差值小于阈值 | `no_difference`（不当成提升） |
| 阈值可配置 | 0.03 差值在 0.01 阈值下判为更好 |
| 基准版本不同 / rubric 版本不同 | `comparable=false`、`inconclusive`、`meanDelta=null` |
| case 集合不同 | 明确写出"候选缺少 case：b""候选多出 case：c" |
| case 重复 | 判为不可比（且不把两侧共有 case 误判为重复） |
| 一侧缺分 | 不可比、`meanCandidate=null`、明细保留有分 case、不按 0 计 |
| 分数越界或非有限（1.5 / -0.1 / NaN / Infinity） | 一律按缺分判不可比 |
| 文案 | 可比时含趋势与差值；不可比时含"不可比""不下结论"与原因 |
| scoreboard 适配 | 百分制换算、缺 case 报不可比、被测对象版本不同不构成不可比 |
| 未配置门禁 | `gate=pass`，成本 +50%、耗时 -10% 如实报告 |
| 成本超阈值 | `gate=cost_exceeded`，写明"成本增幅 40.0% 超过允许的 20.0%"，分数结论不变 |
| 耗时超阈值 | `gate=latency_exceeded`，写明耗时增幅 |
| 配置门禁但缺成本数据 | `gate=unverified`，理由含"成本数据缺失，门禁未核验" |
| 基线成本为 0 | 比例记 null、差额仍给出、门禁不可核验（不写 Infinity 或 100%） |
| 分数不可比 | 资源一并不评估，理由含"分数不可比" |
| 负成本 / NaN | 按未记录处理 |
| 文案 | 门禁未通过带警告与比例；有数据附变化；无数据不出现资源句 |
| scoreboard 成本透传 | 评测的 costUsd/durationMs 进入资源判定并触发对应门禁 |

定向回归：`shadow-comparison` 27 项、`benchmark-versioning` 3 项、`benchmark-store` 5 项、`held-out` 全部零失败；typecheck=0、biome 通过。

实现过程中被自己的用例抓到一个 bug：重复检测最初把"两侧共有同一 case"当成重复（所有正常输入都会判不可比），已修正为只在单侧内部判定重复。

## 边界

- **不是影子流量**：本切片比较的是已落盘的批量评测结果，没有把线上真实请求复制一份给候选侧执行。真正的影子流量（旁路真实流量 + 成本核对 + 不影响用户）尚未实现。
- **成本与延迟只是并列判定，不合并进 verdict**：`verdict` 仍纯粹表示分数方向；"分数更好但更贵"需要人工看 `resources.gate`，本模块不会自动降级或否决候选。
- **成本来自评测记录的 `costUsd`**，是评测进程的估算而非 Provider 账单；真实账单核对与超额追缴仍不在范围内。
- **门禁阈值为产品口径**（默认不设限，由调用方显式配置），不是成本模型的推导结果。
- **不做统计显著性**：阈值法是产品口径的"最小有意义差值"，不是置信区间或检验；`scoreStd` 虽在 scoreboard 里，但本模块不据此判断差异是否显著。
- **未接入 UI/审批流**：模块目前无生产调用方，`compareScoreboardEvaluations` 供后续界面或审批摘要调用；不在本切片声称用户可见。
- 判定前提依赖 scoreboard 记录的 case 分数可信；历史记录不回填、不改写，来源仍需独立审计。

## 空样本与门禁配置校验

对比两侧任一 case 集为空或差值阈值为负数、非有限数时，返回不可比且不生成均值结论；零阈值下完全相同的分数保持无差异。成本或延迟门禁阈值为负数、非有限数时标记未核验，避免 NaN 或无限大使门禁误报通过。新增行为测试先复现四类错误，再验证修复；该纯函数仍无生产调用方，真实影子流量、Provider 账单与人工验收不在本切片范围。

## 基准案例覆盖

scoreboard 对比还会将两侧案例清单分别与调用方提供的基准案例清单核对；两侧同时缺少同一案例、同时含额外案例，以及空或重复基准清单均不产生比较结论。测试覆盖这些情况。历史 evaluation 未保存基准和评分规则版本，这个核对不能证明历史评测确实使用了传入定义；接入生产或用于审批前仍需可信的版本与内容来源，不能把调用方传入的当前版本视为历史证据。

## 历史来源缺失时不推断可比

scoreboard 条目没有记录评测时的基准及评分规则来源，当前基准版本不能证明历史定义。`compareScoreboardEvaluations` 因此在来源机制建立前一律返回不可比、无均值结论和资源门禁未核验，仍保留可读的案例及资源原始明细；不回填、改写或删除已有记录。纯 `compareShadowRuns` 的版本由调用方提供，无法自行验证来源。新增行为测试先复现错误再验证保护，真实 Provider、独立评判与人工验收尚未完成。后续应冻结并记录评测实际使用的案例与评分规则内容及版本，并验证执行过程中没有漂移，再设计新记录的可比路径；历史缺失不能补造。

## 2026-10-31 评测来源与对比报告

新记录保存基准版本、定义摘要及每次运行读取的题目和评分规则摘要；历史记录不回填。自演化每轮产生对比报告并在设置面板展示不可比原因。

基准摘要只覆盖 case 标识、版本和目标；题目摘要不覆盖案例素材、评判者实际实现或运行期间的全部输入。因此当前记录无法证明两侧完整来源一致，`compareRecordedEvaluations` 保守返回不可比，不输出均值差或资源门禁通过。题目摘要缺失或不一致会额外标明。纯 `compareShadowRuns` 接受调用者提供的输入，不自行验证来源。

此报告不改变已有的自演化候选接受逻辑，也不代表业务接受。真实 Provider、独立评判、成本账单及人工验收尚未验证。要开放可比结论，需要先冻结并核对完整案例素材、实际评判来源与运行配置；不推断历史记录具有这些信息。
