# Bash 沙箱写入范围收窄：局部证据

日期：2026-10-28；平台：本机 macOS；范围仅为 `executeBashTool` 使用的 seatbelt 策略，不代表其他 Runtime、文件工具或跨进程隔离已通过。

- 改动前真实沙箱测试发现：会话目录内可写同工作区的 `mcp.json` 和其他会话文件；同目录内 Git 的 `config` 可被写入。两个负向断言均失败。
- 收窄配置目录例外为当前会话工作目录，工作区根不获得整个目录的例外；Git hooks、config、已有 `.git` 入口在例外之后重新拒绝。
- 真实测试确认当前会话可写，兄弟会话与 MCP 配置的直接写入、符号链接写入及沙箱内新建跨会话硬链接被拒；既有 Git 仓库的 hooks/config 不可改，普通 Git 提交与新目录 `git init` 仍可用。
- **未解决：预先存在于工作目录内的硬链接可以引用其他会话文件。** 真实测试复现同一 inode 被修改；保留 `test.skip` 记录该场景，不将 skip 当通过。不能因此宣称跨会话隔离已满足 CA-G1。
- 初始没有 Git 仓库时，为保留单次命令内 `git init`，仅在下次工具调用重新生成策略后才能识别并保护新建的 `.git` 元数据；同一命令内不能宣称 hooks/config 已受保护。伪造 Git 指针与受信 Git 布局绑定仍需单独审计。
- 配置目录其余文件的读取、环境变量、网络与其他工具入口仍未完成隔离；本改动不改变这些承诺。配置目录内、位于当前会话外的 Git 元数据可能因更严格的写入限制而不可用，需以真实工作区配置验证。
- 单文件隔离runner命令：`bun run test bash-sandbox pinned-baseline-verifier`。实际macOS测试的通过/skip详情见运行记录；未调用真实Provider或打包应用。
