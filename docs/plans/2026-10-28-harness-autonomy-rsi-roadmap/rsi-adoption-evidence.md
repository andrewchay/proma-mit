# RSI 候选审批的证据复核

能力候选创建时已有脱敏和样本数检查。批准执行时再次检查至少三条不重复的证据引用仍属于该员工、仍已脱敏且未排除；工作区候选还须匹配冻结工作区。证据删除、排除或缺失时记录执行失败，不激活能力。旧审批若没有证据引用，需要重新生成候选，不补造历史证据。

候选还冻结样本身份、脱敏摘要、执行结果和最新人工判断的 SHA-256 摘要；审批时如证据内容或判断发生变化则拒绝激活。旧候选缺少摘要时需重新生成。定向测试覆盖合法候选、等待审批期间排除或修改样本、缺少引用的旧审批。摘要不是防本地文件篡改的签名，也不证明评测独立性或真实用户认可能力提升。

证据、员工状态和工作区范围在能力版本激活的 SQLite 事务内再次核验；验证失败会回滚整个事务。现有测试验证同连接事务回滚，尚未单独完成跨进程竞争与真实用户验收。

## held-out 完整性

自演化评测循环要求训练集基线和候选 case 完整；启用 held-out 时也必须取得基线与候选的完整 case 集和有限的有效分数；缺失、重复、异常或任一 case 失败时回滚候选，不把缺失分数写成零或声明门禁通过。已持久化的历史记录不回填、不改写；旧分数仍需独立核查来源。员工评测服务对缺失 held-out 总分返回 `held_out_unavailable`，不会创建推广审批。定向测试覆盖真实评测循环中的训练/held-out 基线和候选缺失、模拟 Provider 失败，以及服务决策函数；独立 runBaseline 也在任一训练或 held-out 调用失败时停止并不落盘，训练与 held-out 重叠时在调用模型前拒绝。历史 scoreboard 未改变。尚未完成真实 Provider 和独立评判验收。

## 评判来源与失败

指定模型或注入评判函数后，返回空值、异常、非有限或越界分数均标记该次评测失败，不能静默回退规则分并记录为模型评判；预算耗尽亦如此。仅未指定评判函数时使用规则评分。相同模型标识即使配置了不同渠道也不视为模型区分；注入函数的真实来源无法从配置推断，规则和注入评分不声明独立。界面与审批摘要将原有独立标记表述为配置声明，并明确独立性未经核验；历史记录未改写、仍需审计。不同模型标识也不能证明实际模型或评判流程独立，真实 Provider 与业务验收仍未验证。

## 人工判断来源

学习样本的人工判断投影先定位同一交付与执行的最新验收事件，再要求事件来自本机公共人工入口 `local-user` 且符合当时 reviewer。更新的自动验收或其他尚无可验证人工来源的事件会使该样本的当前人工判断为空，不回退到旧判断；原始事件和样本保留。多用户的认证来源尚未接入此投影，不能仅凭身份目录名称认定为人工。
