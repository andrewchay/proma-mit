# OpenDesign 共享安装的确认依据：证据与候选方案

## 已核实

Owner 共享安装的 `installation.json`、`DESIGN.md` 和 `tokens.css` 同处工作区的 `workspace-files/.opendesign`。读取器核对清单中的 `actor`、来源字段与文件摘要，但这些字段和文件可以一起改写。摘要证明读取时的文件与清单相符，不能独立证明内容来自随包资源，也不能证明用户确认过安装。

在隔离临时目录中手工创建清单和两份文件，给伪造正文计算匹配摘要，并填写 `actor: local-user`、品牌 `stripe` 和虚构版本；直接调用 `readInstalledOpenDesign()` 返回了该正文、品牌和虚构版本。该实验没有调用安装确认入口，也没有访问用户配置。它只证明读取器接受自洽的伪造记录，**不证明某个具体 Agent 已获得该目录写权限**。

源码检查显示 Claude SDK 的附加目录包含 `workspace-files`；是否可写仍受具体权限模式、SDK 和宿主限制，不能仅凭附加目录断言写入成功。Proma 受控 Bash 的 seatbelt 写根为当前 `cwd` 和 scratch，配置目录默认禁止写入，仅对配置目录内的当前会话工作目录开放例外。Pi、Claude SDK、非 Bash 文件工具与其他平台需要各自验证；用户或同一系统账户的其他程序仍可能修改文件。

在 macOS 宿主使用临时配置目录和绑定测试会话，实际通过 Proma Bash 工具及 seatbelt 执行写入：会话目录可写，兄弟 `workspace-files/.opendesign/installation.json` 和配置目录内候选确认登记文件均拒绝写入且内容未变。这验证该会话目录布局下的 Bash 工具路径；它不是完整 Owner 授权流程、其他 Runtime、所有工作目录布局或真实 Provider 的验收。若当前 `cwd` 本身覆盖配置目录或其他进程可写登记，不能沿用此结论。

## 候选：把确认依据移出工作区

1. 应用主进程维护独立于工作区文件的本地确认登记。每条记录绑定项目、Owner 绑定修订、工作区 ID/slug、品牌、随包参考版本、两份文件摘要和用户确认时间；不得从现有 workspace manifest 自动推导确认。
2. 安装预览从随包目录读取并核对版本；明确确认后记录安装事务意图，独占创建文件，再提交确认记录。任何一步失败或进程中断，保持未确认并保留文件和可审计的待处理状态，不自动覆盖或删除已有用户文件。
3. 上下文组装同时核对当前绑定、确认登记、安装文件摘要和登记中的版本。缺项、损坏或不匹配时不声称来源或确认；本地 `DESIGN.md` 的现有优先级保持不变。需明确处理不同项目共享工作区、切换 Owner 绑定及升级后旧资源版本，不得把新版本静默当作旧确认。
4. 登记存放在应用配置目录中的独立位置，并对每个支持的 Runtime 验证其工具、附加目录、子进程与 sandbox 无权改写登记；配置目录位于可写项目内、显式多实例、系统账户的其他进程或缺少隔离时应降级为未验证，不能称为不可伪造。**同目录 HMAC 密钥或普通哈希不能提供独立授权。**

## 已有安装与交互

旧安装缺少独立确认登记，无法安全区分历史真实确认与自洽伪造。候选迁移是在界面展示“旧安装待重新确认”，预览当前绑定、来源版本及文件摘要；用户明确确认后才创建登记，原文件和旧 manifest 保留。内容不完整、摘要不符、来源版本不可验证或绑定变化时拒绝确认，提供可理解的处理提示，不覆盖文件。

这会使旧安装在重新确认前不能作为已确认的共享规范注入，属于用户可见的兼容变化；需要在实现前准备完整预览与重新确认流程，不能只增加后台拒绝。现有用户已确认的范围是 Owner 工作区、显式确认及遇冲突拒绝覆盖；会话目录另存实验不属于该授权。

## 验收与边界

- 隔离测试覆盖伪造清单和哈希、绑定/版本变化、旧记录迁移、确认中断与重试、登记损坏、符号链接、并发创建及失败回滚；验证所有失败路径保留用户文件。
- 各 Runtime 单独验证是否可写确认登记；区分源码推断、模拟测试、真实进程与实际 Provider。多进程并发和断电持久性需单独验证。
- 打包 smoke 使用隔离 profile 和临时工作区，核对 Owner 预览、重新确认、上下文注入和冲突提示；不使用普通用户配置，不把它称为品牌或人工验收。
- 本方案尚未实现或完成权限审计；不承诺对抗同一系统账户的任意进程，也不代表真实 Provider 一定遵循规范。
