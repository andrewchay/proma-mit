# 项目管理用户友好化整改台账

建立：2026-10-06 GMT+8。关联规划：`docs/plans/2026-10-06-project-management-usability/plan.md`（当前整改规划另存于会话工作台 `plan/project-management-usability-remediation.md`）。问题来源：`docs/plans/2026-09-26-project-pilot/usability-blockers.md`。本台账只记录项目管理用户体验整改，不追认 Project Pilot 的 G1/G2/G3 门禁，也不把源码存在或自动测试通过当作真实产品验收。

## 1. 台账口径

| 字段 | 口径 |
|---|---|
| 状态 | 待开始 / 设计中 / 进行中 / 待审查 / 已完成 / 阻塞 / 暂缓 |
| 验收 | 未执行 / 部分通过 / 通过 / 失败；自动测试、固定构建验收、真实用户验收分开记录 |
| P0 | 当前阶段必须先解决的用户阻塞；不解决则用户可能创建无效任务、无法完成决策或无法收口异常 |
| P1 | 在不重写整体 UI 的前提下，让项目概览变成“当前进展 + 下一步行动”入口 |
| P2 | 为 Gravitas 下一阶段 prototype 预留用户层模型和边界，本阶段不提前建设完整新 UI |
| 安全边界 | 主进程/后端继续做最终校验；前端 readiness 只能解释和预检，不能代替授权、预算、工作区、范围、验收和执行门禁 |

## 2. 当前总览

| 项 | 当前结论 |
|---|---|
| 用户目标 | 将项目管理简化为“目标 → 任务 → AI 执行 → 交付 → 验收” |
| 本阶段策略 | 小步整改现有 UI 和编排，不搬运 prototype 的完整独立产品界面 |
| 当前产品判断 | 现有复杂研发闭环虽然有大量治理与安全地基，但当前入口和表单仍不可直接产品化 |
| 首要问题 | 用户可以创建形式上成功、实际上无法进入交付评审链的 AI 任务 |
| 主要成功标准 | 用户无需读源码即可创建有效任务，并能理解每个阻塞的原因和下一步 |
| 当前代码状态 | 仅建立整改规划与台账；本台账建立前未实施本轮整改代码 |
