# 研发 AI 员工（首版）

## 目标与入口

项目管理 → 团队 → 新建 AI 员工 → 使用研发员工模板。

这是既有员工系统的可选 `development` 执行配置，不是新的任务、模型或知识系统。

1. 选择已绑定本地 Git 仓库根目录的工作区。
2. 明确选择已启用的渠道和模型，沿用现有 Runtime。
3. 默认 `safe` 只读诊断；需要开发时显式选择 `auto` 审批执行。
4. 在项目中建立任务，说明复现步骤、期望行为和验收标准，再指派给员工。

保存员工不会启动模型。指派可执行任务才进入既有队列，可能产生模型费用。

## 执行与返工

- 任务指定工作区优先于员工工作区；研发模式没有全局工作区/默认模型回退。
- 首次从干净仓库 HEAD 创建 `employee/<executionId>` 分支及会话私有目录内的 `source/` worktree。
- 源仓库有未提交改动则阻塞，不自动提交、stash、忽略或丢弃当前迭代。
- 任务返工继续同一会话和 worktree，保留未提交代码；新增执行记录，不覆盖旧运行。
- 返工前修改任务说明或完成说明，再将暂停任务切回可执行状态。更换仓库、渠道或 Runtime 时不静默迁移旧成果，请新建任务或恢复配置。
- worktree 缺失或绑定损坏时拒绝运行，不回退主仓库。
- 不自动安装依赖、复制凭据、推送、合并或清理 worktree。依赖配置、外部访问和命令执行按现有审批处理。

## 项目理解与兼容

员工先读实际仓库的 AGENTS.md、README、package.json 和相关实现/测试；按需沿索引读设计，不预置一份易过时的 Gravitas 架构副本。执行指令包含项目描述、任务上下文、上次交付意见、项目与任务 DoD、显式关联的已决策事项。

会话绑定对应 Project 的知识范围，复用现有限域知识检索；员工 Skills 经已有 mention 通道传入，MCP 与工作区配置仍由原 Runtime 处理。项目描述、文档和历史输出不构成权限授权。

未设置执行配置的旧员工保持 `general` 路径，已有 Workflow SOP 继续可用。研发 worktree 尚未贯穿 Workflow 节点，因此研发模式拒绝绑定 Workflow，而不是声称二者已兼容。自定义任务状态按 unstarted/started 语义组派发；draft、paused 和终态不自动执行。

## 权限与验收边界

- `safe` 只读；`auto` 复用现有 Runtime 审批，允许常规编辑，部分命令与敏感操作可能等待用户。不是无限制无人值守。
- 本功能不为研发运行设置 `bypassPermissions`。普通员工的旧权限路径未在本次迁移，不能把研发模式的权限保证推广到旧模式。
- Git worktree 是变更隔离，不是 OS 沙箱，不能保证进程无法访问目录外资源。
- 用户停止、空结果和旧回合回答不计为成功；旧运行不覆盖已改派或人工暂停的主任务。
- 执行完成将主任务暂停并写入“AI 交付待确认”，不写 completedAt，不将已确认任务改回需求草稿 draft；人工完成仍走原项目完成/DoD 校验。
- 执行记录的 completed 只表示运行返回成果，不等于代码正确或业务验收。主进程另外采集分支、基线、Git 状态和 diff 统计为每次运行独立的 JSON 证据；测试命令、退出码和风险由员工报告，仍需核验。此版本未新增自动代码质量验收器或强制双人审查。
- 团队执行记录可展开摘要、工作目录和错误，并打开执行会话查看完整上下文或处理审批。

## 验证与未验收范围

行为测试覆盖临时真实 Git 仓库隔离、配置拒绝、档案持久化、旧档案缺省、返工保留代码、停止/空结果不成功、改派保护、自定义状态和幂等派发。运行器使用确定性测试替身，不调用真实模型。

## 文件委派与人工 Review 闭环（2026-09 新增）

从文件浏览器菜单或任务委派对话框发起：目标/允许路径、已拍板决策、验证命令白名单在派发前确认。执行完成后自动受限提交：冻结快照（含已提交/暂存/未暂存/未跟踪变更），范围外或受保护文件整轮阻塞，员工强制停在 submitted，同任务返工沿用同一交付 id 的新版本。

任务详情内的 Review 面板展示冻结内容差异（非 live worktree）、交付版本与逐项 DoD；验收通过必填依据，退回意见驱动幂等返工。验证服务只采集白名单命令的真实退出码，运行前后工作目录与快照 hash 绑定，漂移即 stale；模型自述的"通过"不作为验证证据。

验收通过后可两段式应用回原仓库：预检要求 HEAD 仍在交付基线、目录与 index 干净、逐文件旧内容匹配；确认后字节级写入，保留为未提交改动，无自动 commit/合并/push。中断按逐文件 hash 分类恢复，混合态标记 recovery_required 待人工处理。应用成功不等于任务完成，仍走现有 DoD 闸门。

新增确定性端到端脚本：`bun run smoke:task-review`（临时配置根与临时仓库，不调用真实模型）。真实 Runtime、审批交互、实际应用自修改、打包安装仍需显式试跑验收；上述闭环的 UI 操作与真实模型路径尚未验收。
