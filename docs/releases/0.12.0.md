# Gravitas 0.12.0：Proactive 运行闭环修复

## 交付范围

本版本聚焦“指定工作区的只读项目未提交变更检查”，不重做全部导航，不开放未验收的 Runtime，不提升主动任务权限。

- 新建会话执行必须明确选择工作区，提供项目检查模板、任务名称和“创建并试跑一次”。试跑保留后续计划，页面明确提示模型费用与本地常驻边界。
- 创建、编辑与执行共用主进程目标校验：渠道和模型启用状态、会话归属、工作区存在及本地目录可用性。不从其他渠道或第一个模型静默回退。
- 每次运行持久化独立完整文本快照，旧记录保留兼容。JSONL 兜底只允许本轮新增消息，避免旧回答伪装为本轮结果；无结果、错误或用户停止不报告成功。新建会话失败保留其 ID 以便排查。
- 首页、定时任务、运行记录共用 Jotai 数据；“运行中”仅取真实运行状态，今日计数不再截断到五条。修复首页暂停按钮，增加空状态配置入口与可见加载错误。
- 首页及运行记录复用运行卡片：完整详情、打开会话、失败重试一次和修复配置。删除来源不删除历史；重试追加新记录，不覆盖失败证据。
- 重启将遗留运行记录标为中断失败，到期任务最多补跑一次；忙碌任务不重复调度。启动恢复推迟到模块初始化完成，避免未初始化状态访问。
- 监听创建支持显式选择模型；触发事件作为不可信数据传入执行提示。运行中页面不再混入全局其他来源的记录。

版本：`@gravitas/electron 0.12.0`；共享运行记录契约增加可选 `output`，`@gravitas/shared 0.1.93`。同步对应 lockfile 工作区版本与自动生成仓库事实摘要。

## 尚未验收与后续范围

- 未调用真实 Provider；未打包安装或替换用户正在运行的应用。因此不宣称“模型端到端 / 安装包验收通过”。
- Pi / Claude 无人值守运行仍不支持，界面明确告知；不能仅放开选择器便宣称支持。
- 主动推荐与 Routine 参数/跨会话资料收集、推荐到 Routine 实例绑定、监听对象级冷却去重、审批完整变更视图仍需后续迭代。
- 当前 `success` 表示执行完成而非业务质量验收。模型可能报告权限不足或检查未完成，用户应查看结果；不能将有文本自动等价为项目检查成功。
- 暂停只停止后续触发，已开始的 Agent 可从对应会话停止。本地应用退出或设备休眠期间不提供云端常驻保证。

## 真实模型验收步骤

1. 在有权限的临时项目中制造一条未暂存和一条未跟踪变更。
2. Proactive → 定时任务 → 项目未提交变更检查模板；选择该项目、已启用渠道与模型。
3. 点击创建并试跑，确认执行中状态；完成后打开详情，核对项目路径、两条变化及完整输出。
4. 暂停任务，不再产生定时触发；保留失败历史后修复配置、重试，确认生成新的 Run。
5. 对照 Git 状态确认检查没有修改、暂存或提交文件。真实模型费用和生产数据访问须由用户明确授权。
