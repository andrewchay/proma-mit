# Proma v0.11.6

> 对比基准：v0.11.5

本次版本完成「AI 员工」P3（Workflow SOP 绑定）——AI 员工路线图 P0-P3 全部落地。方案见 `.context/notes/ai-employees-design.md`。

## AI 员工绑定 Workflow SOP（P3）

- **员工档案新增「绑定 Workflow SOP」**：团队 Tab 新建/编辑 AI 员工时可从已发布 Workflow 中选择一个作为该员工的执行 SOP（卡片显示紫色 `SOP` 标记）
- **执行分流**：绑定后任务自动改用 **Workflow 执行**（`createWorkflowRun` + `executeWorkflowRun`），未绑定仍走 headless 直跑
- **任务上下文注入**：run.input 携带 `taskId / taskTitle / taskDescription / agentName / projectId`，agent 节点 prompt 可用 `<workflow_input>` 引用
- **结果回写**：
  - Workflow 完成 → 任务 completed + 执行摘要（聚合各节点 output）
  - Workflow 失败/取消/阻塞 → 任务回退 paused 可重试
  - Workflow 等待人工审批 → 任务回退 paused 并记录
- **心跳适配**：Workflow 执行（`executor='workflow'`，sessionId 标记 `workflow:<runId>`）不做 Agent 会话存活探测，仅超时检查（默认 60min 可配），避免被误判失联
- **执行记录标记执行器**：`AgentExecution.executor`（headless / workflow），团队 Tab 执行概览可区分

## 架构说明

- 数据层：`agent_employees` 表新增 `workflow_id` 列；`agent_executions` 表新增 `executor` 列（均含 ALTER TABLE 兼容旧库）
- 服务层：`agent-employee-service` 新增 `startAgentWorkflow`（Workflow 路径）+ `extractWorkflowSummary`；`tryStartExecution` 按员工绑定分流
- 渲染层：AgentTeamPanel 员工表单新增 Workflow 下拉（复用 `listWorkflowDefinitions`）

## 升级建议

- 先在「工作流」工作台设计并**发布**一个 SOP（含 agent 节点，prompt 中可用 `<workflow_input>` 引用任务上下文），再到「项目管理 → 团队」绑定到 AI 员工
- 绑定后新指派任务走 SOP；未绑定员工仍 headless 直跑
- 建议 SOP 避免包含人工审批节点（会等待审批而非自动完成）；如需审批，任务会回退 paused 等人工处理
