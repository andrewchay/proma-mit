# HTML Creator

以创意总监的判断完成设计：突出重点，选择合适的信息表达，并让网页与 deck 各自符合其阅读场景。

把已有素材转化为一份能直接给人看的静态 HTML 成品。目标不是把原文贴上页面，而是建立清晰叙事、视觉层级与可信的数据表达。

本目录是此 Skill 的完整交付包：执行时只依赖本文件及同目录的 `references/`。项目根目录中的同类文档仅是这份包的历史参考，不应成为运行时依赖。

按需查阅：

- `references/styles/`：仅在下面的风格表选定一个方向后，读取对应的单风格文件。
- `references/libraries/`：本次实际使用 Tailwind、Reveal.js、Chart.js、Mermaid 或 MindElixir 时，实施前读取对应库的说明；未使用则无需读取。

选择风格时，直接使用本文件的“风格选择”表，再只读取所选风格对应的一个文件。不要一次读取 `references/styles/` 中的全部文件；用户已给出明确品牌或参考时，可以直接按其约束实现而不套用风格库。

**用户展示名**：仅在风格选择或用户要求查看、更换风格时展示，逐字保留“浅色 ·”“深色 ·”或“暖色 ·”前缀，不展示英文 ID。前缀承诺页面的主基底气质；名称应描述实际出现的颜色和可识别画面。

## 用户参考图优先

用户提供网页、PPT、海报或界面截图时，参考图高于风格库。先从可见内容提取阅读路径、构图比例、排印层级、色彩角色、素材处理和 1–3 个标志性结构；再将其转成页面约束，并至少保留一个结构特征。

先还原结构、密度和图文关系，再处理颜色与细节。用用户自己的内容和真实素材替换参考内容；缺少视频、摄影或动态效果时，采用诚实的静态替代。交付前对照首屏和典型内容区，确认主基底、阅读路径、图文比例、色彩角色和标志性结构一致。不得复制品牌标识、原文、受版权保护的图片或私人信息。

## 先判断是否使用

**文档即内容源**：当前正在阅读的文档，或用户明确指定的文档，是本次网页的内容依据。直接提取其核心结论、结构、数据与素材来创建网页，不询问用户“网页想做什么内容”；仅在文档之间存在无法自行判断的冲突时才请求澄清。

满足以下任一情况时使用：

- 用户需要创建网页、可视化页面、落地页、信息图、HTML demo 或网页版 PPT，且已有可用素材：当前文档、会话上下文、表格数据、图片或明确的文案；
- 用户需要编辑、修复、优化或迭代已有 HTML，包括局部文案、样式、布局、响应式、交互、图表或依赖调整。

## 交付后互动提示（**非常重要！！！！一定要出现**）

> 如果这版风格还不满意，直接告诉我“换一个风格”，我会给你几个差异更明显的方向选择。
>

>
> 如果喜欢这个风格，也可以直接告诉我，本次后续修改会沿用这个方向。

## 创意呈现要求

网页和 deck 必须是经过编排的信息体验，不能把原文直接堆成标题、段落和重复卡片。开始前，为核心信息选择合适的表达：

| 信息类型 | 优先呈现方式 |
| --- | --- |
| 核心主张、关键数字、短判断 | 大标题、数字主视觉、留白构图或强视觉锚点 |
| 比较、构成、趋势、分布 | Chart.js 图表、对照版式或有结论的可视化表格 |
| 步骤、阶段、时间变化 | 时间线、阶段图、流程图或路线式布局 |
| 系统、角色、层级、关系 | Mermaid、分层剖面、矩阵或关系图 |
| 品牌、产品、案例、人物、地点 | 真实图片、产品图、UI 截图或经过裁切编排的素材组合 |
| 深度文字、观点、引文 | 杂志式跨栏、重点引语、注释与节奏化留白；不能只堆连续段落 |

为每个主要区块/页面写明“结论、角色、视觉表达、所需素材”。各区块承担主张、证据、解释或行动之一；视觉服务真实内容，不伪造数据或装饰。网页需有以信息为核心的 Hero 和不同的阅读节奏；deck 的相邻页应承担不同角色，避免连续文字页或重复模板。

选定风格后，兑现其基底、配色、排印、布局和标志元素。

所有风格禁止跑马灯、ticker、自动滚动、自动轮播和循环内容轨道。内容较多时使用静态网格、分段、时间线或用户主动切换。

### Hero

除纯工具页外，Hero 应有一个核心判断和信息相关的视觉主角（真实素材、数据或结构），而非居中的标题、说明和按钮模板。首屏只保留必要信息，并在首屏后立即用证据、机制、案例或数据兑现主张；桌面与约 720px 宽度下均应完整可读。

### 执行、素材与交付

- 网页用于连续阅读，确保约 720px 宽度可读；deck 用 Reveal.js，按 1440×810 投屏设计，一页一个观点，信息超出时拆页。
- 数值关系用 Chart.js，流程/关系用 Mermaid，层级结构用 MindElixir；没有可靠数据时用定性表达。
- 品牌与参考冲突时请用户确定优先级；素材缺失时使用清晰占位或删减，不伪造资产。
- 品牌、产品与数据以用户材料或已核验资料为准；只使用已获授权且来源明确的真实素材，并在预览中检查图片。
- 评审时从内容、视觉、品牌、可读性和完成度评分，按“致命、重要、优化”给出修改项。交付前检查网页的 Hero/移动端或 deck 的封面、密集页、结尾页，并说明素材来源、占位和关键假设。

## 风格选择

风格库是没有明确品牌或参考时的决策辅助，不是模板强制。所有运行时、依赖、静态交付和存量 HTML 兼容规则以本文件为准，具体 style 文件不得覆盖它。

1. 用户给出品牌、参考或图片时，优先服从这些约束；若当前会话已确认的风格名与对应形态风格表的“用户展示名”完全一致，则直接使用该风格。风格库只用于补足未指定的部分。
2. 再选温度：创意、活动、青年和宣言内容优先**大胆**；产品、技术和常规商业内容优先**中性**；研究、机构、长文和严谨数据优先**安静**。
3. 最终只选一个风格执行；新建前的候选与选择流程见下节。用户要求换风格或查看其他方向时，同样提供 2–3 个差异明显的选项。
4. 仅在用户具有相应素材或图像能力时，选择依赖手绘、真实摄影、3D、粒子或电影级光影的方向；否则诚实降级为文字、色块、数据图和几何图形。

**通用候选**：“暖色 · 赤陶橙 Claude 风格页”适合产品、品牌、内容、报告与培训等常见任务；触发风格选择时必须包含对应的网页或 Deck 版本，但不覆盖明确视觉约束。

### 新建前确认风格

新建网页或 deck 时，如用户未提供明确的品牌规范、参考图或指定风格，先从对应形态的表中选出 3 个合适候选，再向用户提问，让用户选择。网页与 deck 候选都必须包含“暖色 · 赤陶橙 Claude 风格页”的对应版本。候选必须在主基底明暗和核心布局上明显不同；展示准确的“用户展示名”及一句画面差异说明，不能展示英文 ID 或内部文件名。

收到选择后，只读取对应的一个风格卡并开始创建。用户已给出明确视觉约束、当前会话已确认的风格名与对应表的“用户展示名”完全一致，或明确要求直接创建、不希望选择时，跳过提问并直接采用该风格或约束；编辑已有 HTML 也不触发此流程。

### 通用视觉规则

- 用字号反差、字重、留白、栅格和一个克制的强调色建立层级；不要让所有区块一样大、一样圆或一样有阴影。
- 让每个模块承担结论、证据、解释或行动之一；不要把每段内容都装进卡片。
- 不编造数据、案例、出处、照片或用户评价；无图时使用诚实的纯色、文字、数据图或几何图形。
- 避免无品牌依据的紫色渐变、深蓝底配青紫霓虹 glow、emoji 默认图标、圆角白卡加左侧彩条，以及用无意义装饰填满留白。

## 设计宪法（运行时）

以下原则适用于每次新建或整页重建；编辑已有页面时，在本次修改范围内遵守。

1. **信息层级**：先呈现核心结论，再组织证据、解释与行动；用排版、留白和栅格建立明确主次，不平铺原文。
2. **风格匹配**：让视觉方向服务内容、受众和使用场景；品牌或参考优先于风格库，没有依据时选择克制、可信的实现。
3. **可读性**：正文、标题、表格和图表保持足够的字号、对比度、行高与留白；中文优先保证自然断行和阅读节奏。
4. **内容真实性**：不编造数据、案例、来源、评价或图片；数据不足时用定性表达，明确不确定性，不伪造精确结论。
5. **响应式**：桌面与手机均可阅读和操作；空间不足时重排、拆分或翻页，不将桌面页面等比缩小。
6. **视觉节奏**：让每个区块承担结论、证据、解释或行动之一；在密度、留白和强调之间形成节奏，不让全页平均用力。
7. **避免模板化**：不重复堆砌同款卡片、装饰、阴影、渐变或动画；每个视觉元素都应承担信息或品牌任务。

### 编辑已有 HTML

编辑已有 HTML 时，也必须使用本 Skill 并遵守全部适用约定。先读取完整现有 HTML，识别页面形态、已加载依赖、数据图表、外链、素材与响应式结构；再以最小必要改动完成用户要求。不要因局部文案或样式调整而无关重构整页；但若现有实现触犯本 Skill 的安全或静态交付约定，应在本次修改范围内一并修正，或向用户说明无法安全保留的原因。

**存量 HTML 兼容。** 编辑未引入下述库的旧页面时，不要仅为符合本 Skill 的新建页规则而补引 Tailwind、Reveal.js 或 Chart.js。保持原有的原生 HTML/CSS/JS 架构，用现有方式完成局部文案、样式、布局、响应式和简单交互修改。只有用户明确要求新增相应能力，或本次新增功能确实需要该库且原生实现不合适时，才按“按需加载”规则引入；新增前说明理由与影响。旧页面原有的可读性、外链安全和静态交付问题仍应在修改范围内修正。

## 制作与交付

1. 创建页面时，先读取全部已提供素材，抽取：目标受众、核心结论、可信数据、可用图片、品牌线索和来源。编辑页面时，先读取完整现有 HTML 与用户要求，再识别受影响的模块和约定。
2. 在开始写之前确定信息架构、一个设计方向、调色、图表和关键模块。决定后一次完成，不在同一轮推翻并重写整页。
3. 默认生成单个完整 HTML 文档。大改（超过五处、换结构或换风格）重建完整文档；小改先读回 HTML，再以唯一匹配的原文精确替换。使用当前可用且已获授权的工具创建、读取、编辑和验证，不绑定特定工具名或交付通道。

### HTML 交付约定

- 单文件完整文档：`<!doctype html>`、`html`、`head`、`body` 齐全；`meta charset` 和 viewport 必须存在。
- 静态内容交付：在生成时把数据展开成最终静态标签，或把数据块嵌入页面、由页内极简脚本渲染。内容本身应可独立阅读，不要求接入后端或数据库。库、图片和字体可按需加载；静态交付不等于禁止资源请求。
- CSS 写在 `<style>`，少量交互 JS 写在 `<script>`；图标与装饰插画优先内联 SVG 或 CSS。
- 图片使用已获授权、来源明确且交付后可访问的资源；路径、URL 或内嵌方式按交付需要选择，并检查加载结果与文件体积。
- 链接使用语义化 `<a>`，按阅读需要选择当前页或新窗口打开；新窗口外链添加 `rel="noopener noreferrer"`。脚本新开窗口时同样隔离 opener，不将未校验的输入直接用于跳转。
- 页面必须桌面与手机可读：弹性或网格布局、`clamp()` 字号与小屏断点；不要把桌面画布等比缩小到手机。

### 库：按需加载

只加载页面实际使用的库。不要为普通滚动页加载 Reveal.js，为没有量化图表的页面加载 Chart.js，或为简单的静态列表加载 Mermaid / MindElixir。编辑未使用这些库的存量 HTML 时，适用“存量 HTML 兼容”规则，不得为对齐新建页规范而强制补引。

资源可选官方分发、可信 CDN 或本地文件，不固定域名和白名单。明确所用版本与构建格式，核对 API、CSS/JS 配套关系和加载顺序；不要混用不兼容版本。库无法使用时，采用原生静态表达并说明能力变化，不伪造已实现的功能。

- **Tailwind：通常需要时加载。** 使用 utility class 完成常规视觉与布局时，加载 Tailwind，并优先用于间距、Grid/Flex、响应式、颜色、字号、边框、状态和位置。极简、少量样式的原生 HTML 页面可不加载。`<style>` 保留主题变量、Reveal 局部覆写、复杂伪元素、动画，以及「重复 ≥3 次」的语义化组件类（把高频 utility 组合收敛成 `.card`、`.eyebrow`、`.body` 等短类，属性值与 Tailwind 等价）。一次性布局不用自定义类；已选择 Tailwind 时，不得用手写 CSS 重造其整套布局能力。最小用法见 [Tailwind](references/libraries/tailwind.md)。
- **Reveal.js：仅新建 deck 需要。** 新建网页版 PPT/翻页演示时，同时加载 Reveal CSS 和 JS，使用 `.reveal > .slides > section` 结构并调用 `Reveal.initialize()`。每页都必须用统一的 `.slide-content` 内层容器负责内容布局与垂直对齐，不能只让封面或结尾页临时居中；垂直对齐由 `section` 在 `present`/`past`/`future` 状态下作为 flex 容器、`.slide-content` 用 `flex: 1` 撑满画布实现，**禁止给 `section` 覆盖 `position`（尤其 `position: relative`）或依赖 `min-height: 100%`**。翻页、键盘、触控、控制按钮、进度和页码全部交给 Reveal，不自行重造。连续滚动网页不得加载 Reveal；编辑未使用 Reveal 的存量 deck 时，按“存量 HTML 兼容”规则保留其实现。Deck 必须按 1440×810 画布的投屏阅读距离设计，不能沿用普通网页的小字号。最小用法见 [Reveal.js](references/libraries/reveal.md)。
- **Chart.js：仅新建量化图表需要。** 当新建页面或本次需求要新增趋势、比较、构成、分布或多期等量化关系图表时，加载 Chart.js，并用 `canvas` + Chart.js 生成图表。仅展示 KPI、数据表、文字结论或无数值的定性流程/架构图时，不加载 Chart.js；编辑存量页面但不新增图表时，不因页面已有数值而补引 Chart.js。不得以手写 SVG、CSS 宽度条、div 柱图或字符图冒充本应使用图表表达的数据关系。最小用法见 [Chart.js](references/libraries/chartjs.md)。
- **Mermaid：仅新建定性关系图需要。** 当页面需要稳定生成的流程图、时序图、状态图、类图、架构关系或用户旅程时加载 Mermaid。把图的源数据保留为简短、可读的 Mermaid 文本，以便后续改节点或连线；不要手写 SVG 替代这类图。简单的 2–4 步线性说明可用普通 HTML 阶段卡，纯层级知识结构应优先用 MindElixir。默认用严格安全级别，不使用用户提供的 HTML 标签、`click` 指令或外链跳转。最小用法见 [Mermaid](references/libraries/mermaid.md)。
- **MindElixir：仅新建静态层级脑图需要。** 当内容核心是从一个主题向多层分支展开时，加载 MindElixir 的配套 CSS 与脚本，并按所选构建的导出方式取得构造器。把节点写为 `nodeData` 树形数据，使用稳定、唯一的 `id`；不要用它表达有先后、循环、条件或多对多依赖的流程，那些关系应使用 Mermaid。脑图不提供用户拖拽、滚动、缩放或编辑能力；容器必须有明确高度并隐藏溢出，首次渲染时可调用一次 `scaleFit()` 使内容完整可见。页面正文仍须保留核心结论，不能只留下难以检索和阅读的画布。最小用法见 [MindElixir](references/libraries/mindelixir.md)。

## 信息设计流程

### 1. 先提炼，再排版

把素材压缩为一个中心判断和 3–7 个支撑点。优先采用下列叙事之一：

- **结论—证据—含义—行动**：研究、商业与行业报告。
- **问题—洞察—方案—收益**：产品、方案与落地页。
- **时间线—现状—转折—展望**：趋势与复盘。
- **背景—方法—发现—建议**：专业分析。

每个区块只承担一种任务：陈述结论、展示数据、解释机制或引导行动。避免把所有资料都做成卡片，也不编造数据、案例、引文、用户评价或来源。

### 2. 为数据选对表达

| 信息关系 | 首选表达 |
| --- | --- |
| 随时间变化 | Chart.js 折线图、面积图；无量化时用时间线 |
| 类别比较 | Chart.js 排序条形图或点图 |
| 总量构成 | Chart.js 堆叠条、100% 堆叠条；类别很少才用环图 |
| 明确的步骤、条件、循环、角色协作 | Mermaid 流程图、时序图、状态图 |
| 多层主题、发散归类、知识树 | MindElixir 思维导图 |
| 简短过程/角色（2–4 步） | 原生箭头流、阶段图、分层架构图 |
| 单个最重要数字 | 大数字页或 KPI 区块 |
| 引用、条件、定义 | 简洁注释、脚注、来源行 |

图表服务一个结论：标题写结论而非「数据图」，单位清楚，颜色不超过必要数量，文字标签优先于依赖图例。数据不足或不可比较时，使用定性结构图，不伪造精确图表。

## 代码量与可维护性（信息密集页面）

内容密集的文档/知识库页，代码量的大头通常是重复结构而不是内容。按顺序做三件事：

1. **先量化再动手**：用 `rg -o 'class="[^"]*"' | sort | uniq -c | sort -rn` 统计重复组合，只收敛出现 ≥3 次的模式；一次性的样式维持 utility class。
2. **内容数据化 + 固定模板**：同构模块（卡片列表、表格、月份格等）把内容收进数据数组，由页内极简脚本或生成期展开为 HTML。加内容 = 加一行数据，不要复制整块标签。实测同一知识库页：数据版比全量 HTML 少约 40% 行数。
3. **动态注入注意**：按所选 Tailwind 版本和使用方式处理样式生成；使用运行时生成样式的方式时，要等待新增内容的样式生效；使用预编译 CSS 时，要确保构建包含所需类。注入的 class 写完整字面量，避免拼接导致扫描遗漏。初始化时测量布局的代码（如 Chart.js）应在相关样式、字体和容器尺寸就绪后执行，不把 `load` 事件或固定延时当作所有情况的保证。

不要仅为省几行代码引入 Vue/React 等框架；先评估依赖体积、维护成本和实际复用收益，简单静态内容优先原生实现。

### 3. 决断式选一个设计方向

优先从用户的品牌、参考和内容气质出发；没有明确方向时，从下面选**一个**适配方向并执行，不给用户堆三个相似方案。风格库是弹药，不是模板强制。

按上面的风格表选定一个方向后，只打开对应的单风格文件；其内容只决定视觉 DNA，具体实现仍服从本文件中的 Tailwind、Reveal.js、Chart.js 与系统字体规则。

不要把「AI 生图专用」的梦幻超现实、写实场景、人像或复杂材质默认塞进 HTML；只有用户明确给出可用图像能力和素材时才使用真实图。图像提示描述 mood、材质和主题，不描述整张网页布局。

## 视觉执行标准

### 排版与颜色

- 默认使用系统字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；需要代码/数字时加入 `ui-monospace, SFMono-Regular, Menlo, monospace`。品牌或风格需要时可使用已获授权的 webfont，同时提供回退字体并检查加载后的布局。
- **中文排版优先。** 中文正文默认 `font-family: "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`、`line-height: 1.7–1.9`、`letter-spacing: 0–.03em`；不要把英文式全大写、宽字距或窄行高直接套在中文上。中文标题每行优先 8–16 字，使用中文标点，不强制逐字断行；长英文、数字与代码可使用 `ui-monospace` 局部承载。正文容器使用 `word-break: normal; overflow-wrap: break-word; line-break: strict;`，避免中文在标点前断行或被等比压缩。中文表格、标签和 deck 正文须保留更宽内边距与至少对应字号下限；信息放不下时拆模块/拆页，而非缩小中文。
- 用明显的字号、字重、行高、字距和留白建立层级。标题可使用 `clamp()`；中文标题优先用「」；启用 `text-wrap: pretty`（可用时）。
- 在 `:root` 定义背景、文字、弱文字、强调色、边线、间距与圆角变量。一个主强调色贯穿全页，最多配一个功能色。
- 用 Tailwind 的 Grid/Flex utility 做版式。卡片应有信息必要性，避免所有内容都成为同样的圆角卡片。
- 预留真实的图片/图表位置；没有图片时可使用诚实的色块、数据图或 SVG 几何，而不是生成畸形的人物/物体插画。

### 明确避开

- 无品牌依据的紫色科技渐变、深蓝底配青紫霓虹 glow。
- emoji 充当默认图标；需要图标时使用少量一致线宽的内联 SVG。
- 「圆角白卡 + 左侧彩色竖条」的默认模板感。
- 全页平均分配、相同字号、相同留白、相同卡片；应有主次与节奏。
- 跑马灯、ticker、自动轮播、自动滚动内容条、循环内容轨道及其他自动播放的展示；无论是否“有必要”均不得使用。
- 伪 3D、虚假数据与无意义装饰。

## 注意事项

- 所有数字、日期、单位、推断和来源是否忠实于素材？
- 是否只有一个明确风格，并且与内容/受众相配？
- 图片和字体是否已获授权、来源明确且交付后可访问？是否检查了加载结果、回退方案和资源体积？
- 是否只加载实际使用的资源？使用 Tailwind utility 时是否提供对应样式，极简原生页面是否避免了无意义依赖？编辑未使用相关库的存量 HTML 时，是否避免了为了对齐规范而强行新增依赖？
- 重复 ≥3 次的 class 组合是否已收敛为语义化类？
- 页内脚本注入的内容是否用完整 class 字面量？Chart 等测量类初始化是否在样式就绪后？
- 每个依赖是否来源可信、路径有效，且版本、构建格式、API 与 CSS/JS 配套一致？
- 如果是 deck，是否同时加载并真正初始化 Reveal？如果页面用量化关系图表表达数据，是否加载 Chart.js 且每张图都由 canvas 生成？
- 如果页面有定性流程、时序、状态或架构关系，是否加载并实际运行 Mermaid，且选择的图种匹配关系、`securityLevel` 为 `strict`、节点没有塞入长段文本？Mermaid 是否在库可用后配置 `startOnLoad: false` 与主题，再在节点就绪后调用 `mermaid.run()`，且没有重复触发自动与手动渲染？
- 如果页面有静态脑图，是否加载配套 MindElixir CSS 与脚本、按实际构建的导出方式初始化，节点 id 是否唯一、容器是否有明确高度和 `overflow: hidden`，并已关闭拖拽、缩放、滚动与编辑？是否确认相关样式、字体和容器尺寸就绪后才初始化，并在下一帧 `scaleFit()`？脑图及其 Grid/Flex 外层是否设了 `min-width: 0` / `min-w-0` 和 `max-width: 100%`？若按页面需要传入自定义主题，`theme.type` 是否显式设置、`palette` 是否为数组，深色页的 `--bgcolor` 是否与页面背景一致，`--line-color` 与 `--line-color-selected` 是否有足够对比度？流程、条件和依赖关系是否没有错误地画成脑图？
- 如果是 deck，每个 `section` 是否都有 `.slide-content`？`section` 是否保持 Reveal 默认定位（未覆盖 `position`），垂直居中是否由 `present`/`past`/`future` flex 容器 + `.slide-content` 的 `flex: 1` 撑满画布实现（而非 `min-height: 100%`）？是否只有明确标记为 `slide-content--top` 的高密度页贴顶，其余内容页、封面和结尾页都在画布中垂直居中？
- 如果是 deck，是否实际检查第 1 页和最后一页？封面/结尾的类选择器是否直接命中 `section`（如 `section.cover`，而非 `.cover section`），背景是否已生效，标题和副标题是否与背景具有足够对比度？
- 如果是 deck，是否按 1440×810 画布检查过一页卡片/表格最密集的页面？正文是否至少 `text-xl`、表格至少 `text-lg`、标签至少 `text-base`，且没有把 `text-xs` / `text-sm` 用作可见内容？
- 如果是 deck，标题之外是否避免 `leading-none` / `leading-tight`？正文与卡片是否使用 `text-xl leading-relaxed`，表格是否使用 `text-lg leading-[1.5]` 且单元格至少 `px-4 py-3`？
- 链接打开方式是否符合阅读需要，新窗口外链是否隔离 opener，所有跳转目标是否安全？
- 720px 左右宽度下是否仍可读、可点、无横向溢出？
- 图表是否表达结论，且没有伪精确或难以阅读的图例？
- 是否删掉了无意义卡片、emoji、通用渐变、重复装饰和无效动画？
- 网页的 Hero 是否有视觉主角、兑现风格，并在首屏后展开主张？
- 若有参考图，成品是否保留其主基底、阅读路径、图文比例、色彩角色和标志性结构？
