## 测试领域

三轮迭代均以同一业务领域为试验场：**某二次元手游(原神)的流失用户召回**。
- 已知背景：假期窗口是回流主驱动；缺口框架 `目标1000万 = 自然基线735万 + 召回增量265万`；缺口三分解(内容选择红利/触达效率/端内承接)；付费分层(大R>2000/中R300-2000/小R<300)。

---

## 第一轮（2026-06-30）narrow 内联跑

8 视角产 8 候选，select 后命中率约 **1.5/7**（仅"版本候鸟"完全过关、半个"KPI即病灶"）。暴露三个问题：

1. **【已修】生成停在「应该X」层**：多个候选产出"应该识别负价值用户""应该看他们在找什么"——把球踢回用户。
   → 修法：强制 `falsifiable_hypothesis` + select 增设 `hypothesis_is_specific` 筛。
2. **【待 Q3】finder 太通用 → 候选不领域特异**："召回失败是追赶绝望""KPI激励灌水"换任何游戏都成立。
   → 指向 Q3。
3. **【方法论局限】narrow 内联 = 单人单次，视角伪多样**：8 候选雷同地落在"分层/识别"。
   → 结论：必须用 wide 扇出对比才能公平评判。

## 第二轮（2026-06-30）wide 扇出回归（210 agent / 1.97M token / 32min）

48 生成视角 → 162 候选。**两修复验证成功，一新缺陷暴露**：

- ✅ 强制假设生效：top 候选假设全部具体带双向证伪阈值（如"holdout 自然回流率覆盖缺口≥30% 则成立，<10% 则我错"）。
- ✅ wide 多样性远胜 narrow：top10 全 genuinely_new，四个独立 agent(P09×西蒙/P09×拉波夫/P13×西蒙/P11×拉波夫)从不同组合**独立收敛到同一要害**——「缺口分解的分母(735万/265万)本身可能是错的」。
- 4. **【已修】孤立式 select 退化为辩护**：162 候选 **0 淘汰**。修法两阶段(Stage1默认kill+兜底硬阈值 / Stage2横向barrier去重)。修复后 162→35→12簇，"分母错了"四候选合成一簇。

## 第三轮（2026-07-01）Q3 厚 finder 受控 A/B

同一 `P11 逆向 × 卡尼曼` 组合、同领域、同输入，唯一变量带不带卡尼曼厚轨迹：

| 维度 | 不带 trace | 带厚 trace |
|------|-----------|-----------|
| 领域特异性 | 换任何产品都成立("理性退出者""锚定伪缺口") | 咬住游戏特有结构(大版本高光期/抽卡/UP角色/付费分层) |
| 排除省事解释 | 直接给结论 | 学会"排除噪声"(候选明写"超过自然衰减") |
| 共享机制 | 单个偏差 | "一个机制预测多个偏差"(UP/联动/剧情高潮版本被系统高估) |

**最强证据**：带 trace 的候选产出"代表性启发式让策划高估'像爆款'的版本"——一句话 finder 永远产不出的结构。
