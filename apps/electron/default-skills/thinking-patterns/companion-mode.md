# 伴随模式设计文档 (Companion Mode) —— Q1

> thinking-patterns 的第三种模式。前两种(诊断/发现)都是**行动前**的——你坐下来给工具一个命题或领域，它跑一轮给结果。
> 伴随模式是**行动中**的——它在你做研究的过程里持续在场，捕捉"意外/摩擦"并即时 triage。

## 一、为什么需要"行动中"——Schön 的 reflection-in-action

设计依据是 Donald Schön《反思性实践者》：专业人士的核心能力不是"先想清楚再做"，而是**在动手过程中，材料会回话(back-talk)，意外迫使你当场重新定义问题**。最好的研究问题很少在书桌前想出来，而是在实验失败、数据不对劲、用户反应出乎意料的那一刻浮现。

前两个模式结构上是"行动前"的，且**无状态**——跑完就忘。这漏掉了一整类问题发现：**做着做着撞出来的**。伴随模式补这个缺口。它对应范式库里的 **P22 行动中反思**(BS5 可言说性盲区里唯一被坐实的范式)。

## 二、它和前两个模式的根本区别

| | 诊断模式 | 发现模式 | 伴随模式 |
|--|---------|---------|---------|
| 时机 | 行动前 | 行动前 | **行动中** |
| 输入 | 一个命题 | 一个领域 | **一个意外/摩擦** |
| 状态 | 无状态 | 无状态 | **有状态(journal)** |
| 触发 | 用户主动调用 | 用户主动调用 | **半自动(Agent 识别信号)** |
| 产出 | 批判报告 | 候选问题簇 | **"这个意外是不是新问题"的即时判断** |
| 规模 | 单次 | 多 agent 扇出 | **轻量(3问 triage)** |

## 三、半自动触发——Agent 在对话中识别"意外信号"

伴随模式不靠用户记得调用，而是 **Agent 在协助研究的过程中主动识别**以下信号，识别到就提示"要不要记一笔 + 跑个 triage"：

**意外信号清单(听到这些就警觉)**：
- 明确的意外词："奇怪""不对劲""没想到""怎么会""按理说不该""反直觉"
- 实验/分析失败："跑不通""结果不显著""和预期相反""数据对不上"
- 被解释为噪声的反复出现："又出现了""总是""这批数据老是"
- 计划被现实打断："本来想…但发现""原计划行不通"
- 用户对自己结论的犹豫："我以为…其实""好像哪里有问题"

**识别后 Agent 的动作**(不打断心流，轻提示)：
> "这听起来像个值得记的意外——要不要我记进 journal 并快速 triage 一下它是不是在指向新问题？"

用户同意才记+triage；用户说"先不"就继续手头的事。**宁可漏报不要误报到打扰**——Cleese 的开放模式提醒：过度干预会杀死开放状态。

## 四、三问 triage(不跑全部 21 范式，60 秒)

捕捉到一个意外后，只跑三个最相关的范式，快速判断它的性质：

1. **P02 异常驱动**：这是噪声还是信号？——它朝同一方向反复出现吗？还是一次性偶然？
2. **P22 行动中反思**：它在重新定义问题吗？——这个意外是否说明我原来要解的问题问错了？
3. **P19 死胡同剖析**：它会不会是伪线索？——这个"意外"会不会是工具赝象/观察偏差，追下去是死胡同？

**三问的产出是一个分流判断**：
- 信号 + 重新定义了问题 → **升级**：这可能是比原课题更好的问题，建议转**发现模式**深挖或直接立为新方向
- 信号但没重定义 → **记录**：存进 journal 的意外流水，积累待后续看模式
- 噪声/伪线索 → **存疑**：记一笔但标记低优先，避免被一次性偶然带偏

## 五、journal schema(状态持久化)

文件位置(用户指定，默认工作区级)：
- **工作区级** `workspace-files/.context/research-journal.md`：跨会话长线课题
- **会话级** `<cwd>/.context/research-journal.md`：单次任务

结构(按课题分块，意外追加在各课题下)：

```markdown
# Research Journal

## 课题: <课题名>
- **当前问题表述**: <随认识深化会被改写，保留改写痕迹>
- **意外流水**(新的加在下面):
  - [日期] 意外: <发生了什么> | triage: 信号/噪声/伪线索 | 是否重定义问题: 是/否 | 处置: 升级发现模式/记录/存疑
  - ...
- **已升级为新方向的**: <从意外里长出来、值得正式追的问题>
```

**journal 的价值在累积**：单个意外可能是偶然，但 journal 让你回看"同一个意外反复出现"——那才是 P02 说的真信号。无状态工具看不到这个跨时间的模式。

## 六、三模式如何闭环

```text
伴随模式(行动中捕意外) ──升级──> 发现模式(领域→候选问题) ──候选──> 诊断模式(批判单个命题)
        ↑                                                              │
        └──────────────── 带着更锐利的问题回到研究行动 ←────────────────┘
```

- **伴随→发现**：journal 里积累的某个反复意外，升级成"以它为种子的领域扫描"
- **发现→诊断**：发现模式产出的候选问题，喂回诊断模式做二次批判
- **诊断→伴随**：批判后带着更清晰的问题回到研究，在行动中又撞出新意外

三模式不是三个孤立工具，是问题发现的一个**完整循环**：行动中冒出→发散生成→收敛批判→再回行动。

## 七、已知局限(诚实标注)

1. **半自动识别会误报/漏报**：Agent 判断"这算不算意外"本身不可靠。宁可漏报——误报打扰的代价高于漏报。
2. **journal 靠纪律维护**：如果用户/Agent 不持续记，它就空转。它是习惯的脚手架，不是自动捕获器。
3. **三问 triage 是快筛不是定论**："信号/噪声"的判断在 60 秒内做不准，只为分流，真要确认仍需诊断模式或实际验证。
4. **未实测**：截至建档(2026-07-01)伴随模式尚未在真实长线课题上跑过，三问 triage 的有效性待验证——这与诊断/发现模式不同，后两者已有实战测试记录(见 `test-logs.md`)。
