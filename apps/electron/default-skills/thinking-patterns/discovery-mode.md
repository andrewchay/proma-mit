# 发现模式设计文档 (Discovery Mode)

> 本文档定义 thinking-patterns 的第二种工作模式。它不是对诊断模式的改良，而是一种**结构上不同的东西**。
> 设计依据见会话讨论：诊断 = tester(批判已上桌的命题)，发现 = generator(产出尚不存在的候选)。

## 一、为什么发现比批判难——两种模式的本质区别

| 维度 | 诊断模式(现状) | 发现模式(新增) |
|------|---------------|---------------|
| I/O 契约 | 命题 进 → 批判 出 | 领域+已知+好奇 进 → 候选问题 出 |
| 形状 | 消减性(convergent) | 发散→消减的循环(divergent→convergent) |
| 本质角色 | tester | generator + selector |
| 单次/迭代 | 单次 pass | generate→select 循环 |
| 失败模式 | 把旧问题措辞更精确，误以为是新问题 | 候选过多/全是平凡组合/筛选标准失灵 |

**核心约束**：无法批判一个还没被放上桌的东西。诊断模式的 21 范式被当成「检查项」在用，所以整体是批判形状的——即使其中 P04/P09/P13/P11/P15/P22 本质是生成性范式，也被压成了 verify 档。发现模式把这些范式切到 **generate 档**。

## 二、发现 = 生成性扇出 → 消减性筛选

```text
发现模式 = generate（divergent）           → select（convergent）
           生成性范式 × finder母结构 扇出      P19/P01 + fertility三维 筛
           产出大量候选问题                    幸存者 = 候选好问题
```

### generate 引擎：用什么生成候选

复用 KB 已有的两类资产，叉乘扇出：

**(A) 6 个生成性范式（切到 generate 档）**

| 范式 | generate 档动作 |
|------|----------------|
| P04 跨域类比 | 把你领域的深层结构匹配到另一成熟领域，那边已回答的问题在你这里的对应物 = 候选 |
| P09 无知地图 | 列出本领域「默契绕开、从不正面问」的空白，每个空白 = 候选 |
| P13 尺度跃迁 | 把现象的时间/空间尺度放大缩小几个数量级，新尺度上冒出的现象 = 候选 |
| P11 逆向提问 | 不问「为什么是现在这样」，问「为什么偏偏不是其它本可能的样子」 |
| P15 原则扫描 | 用一条你看重的原则扫现状，每个「违反却被当理所当然」处 = 候选 |
| P22 行动中反思 | 从你实践中遇到的「出乎意料」反推被它重新定义的问题 |

**(B) 8 个 finder 母结构（来自 cross-domain-index.yaml）**

每个 finder 是一个可跨域迁移的「问题发现内核」，当成探照灯扫用户领域：

| Finder | 母结构 | 扫描提问 |
|--------|--------|---------|
| 冯·诺依曼 | 公理化 + 推到极限 | 你领域的公理是什么？极限处暴露什么？ |
| 西蒙 | 有限理性 | 在认知/信息/算力有限约束下，你领域的「最优」该如何重新定义？ |
| 图灵 | 概念操作化 | 你领域最含糊的大问题，能换成什么精确的形式装置？ |
| 鲁宾 | 反事实框架 | 你关心的因果，能否定义为「潜在结果之差」=缺失数据？ |
| 霍兰德 | 适应=种群上的算子 | 你领域的「改进/学习」能否操作化为种群上的算子？ |
| 霍普菲尔德 | 整体搬入物理结构 | 物理的能量景观/相变能否整体搬进你领域？ |
| 卡尼曼 | 质疑理性假设 | 你领域默认人/agent是理性的吗？把它当可被实验打脸的靶子 |
| 拉波夫 | 噪声其实是信号 | 你领域被斥为「噪声/错误/变异」的东西，有没有隐藏结构？ |

> generate 的威力来自**叉乘**：6 范式 × 8 finder = 48 个生成视角，每个产 1-3 个候选 → 几十到上百候选。这正是适合 Workflow 多 agent 扇出的形状。

### select 引擎：两阶段（对抗初筛 + 横向收敛）

> ⚠️ 教训（见七.4）：早期版本让 select agent「逐候选独立打分」，结果它退化成「为每个候选辩护」——wide 跑 162 候选 0 淘汰。修复后改成**两阶段**。

**Stage 1 — 对抗式初筛（逐候选并行，但默认 kill）**
agent 的默认裁决是 **killed**，必须先写出「最致命的一条反驳」(strongest_objection，禁止写"无")，只有当反驳能被实验设计干净化解、且问题打到平凡问题打不到的根基时，才 survives。三道老筛并入其中：
1. **P19 死胡同剖析**（杀伪问题）：对照 `Z-dead-ends.yaml` 八种死法
2. **P01 基础假设质疑**（杀循环论证）
3. **假设具体性**：踢皮球式「应该研究X」直接毙
- **程序化兜底**：即便 agent 心软，代码层再拦——自评反驳致命却放行的、假设不具体的、重要性<4 的，一律出局。

**Stage 2 — 横向收敛（barrier，通看全部）**
这是逐候选筛【做不到】的事，必须等 Stage 1 全部完成后一次性通看：
1. **去重合并**：指向【同一底层要害】的候选合并成一簇（如多个候选其实都在质疑同一个分母/口径/单元），选最锋利的当代表。
2. **强制淘汰**：平凡的、与他簇重复的、杠杆低的，填进 dropped_idxs，宁多勿少。
3. **限量**：最多 `max(5, ⌈幸存数/3⌉)` 簇，按杠杆排序。

**fertility 三维**（可解性 × 重要性 × 被忽略性，复用 work_schema 字段）在 Stage 1 打分、Stage 2 排序时复用。最终输出**簇**而非散落候选，每簇含代表问题 + 被合并的同源问题 + 为何高杠杆。

## 三、I/O 契约

**输入**（不再是单个命题）：
- `领域`：你在哪个领域找问题（如「LLM 可解释性」「游戏用户留存」）
- `已知`：这个领域你已经知道/已被解决的（避免重复生成已知问题）
- `好奇`：你隐约觉得有趣但说不清的方向（可选，给生成加偏置）

**输出**：
- 5-10 个候选问题，每个标注：`来源(范式×finder)` + `三维打分` + `为何比平凡问题好`
- 明确区分：哪些是「真新问题」，哪些只是「旧问题的精确化」(诚实标注，对应诊断时发现的失败模式)

## 四、何时用 workflow vs 内联

- **内联跑（skill 直接做）**：领域很窄、用户只想要几个方向、不追求穷尽 → 主 agent 直接挑 3-4 个高相关 finder×范式 组合手跑。
- **Workflow 扇出（discovery-workflow.js）**：要系统性穷尽、领域宽、希望多视角并行不互相污染 → 调 Workflow，每个 generate agent 持一个 finder+范式 独立产候选，再一道 select pass 收敛。
  - ⚠️ Workflow 需用户显式 opt-in（成本高、agent 多）。skill 里要先问用户要不要扇出，而非默认调用。

## 五、与诊断模式的关系

两模式共享同一个 21 范式引擎，但工作流相反：

- **诊断**：命题 → 跑 diagnostic_questions（批判形状）→ 报告
- **发现**：领域 → 跑 generate operations（生成形状）→ 候选 → 跑 select → 排序

发现模式产出的候选问题，可以**直接喂回诊断模式**做二次批判——这是两模式的天然衔接，也是「先生成后筛选」循环的闭环。

## 六、已知局限（诚实标注）

1. **组合不等于洞察**：48 个视角大多产平凡组合，select 必须够狠，否则用户被候选淹没。
2. **finder 母结构是压缩的**：当前只有一句话母结构，生成质量受限。若 Q3(exemplars 补被否决分支)落地，finder 会更有生成力。
3. **仍在工具的认识论框架内**：generate 引擎来自「成功案例」归纳，撞 BS1-BS5 盲区时，生成的候选同样偏向西方个体科学家模式的好问题。

## 七、实测验证小结（具体测试记录见 `test-logs.md`）

发现模式经三轮真实测试迭代（一个业务领域为试验场，详细数据与案例在 `test-logs.md`）。此处只留**通用方法论结论**：

**第一轮 narrow 内联**暴露三个问题：
1. **【已修】生成停在「应该X」层**——候选把球踢回用户。修法：强制 `falsifiable_hypothesis` + select 增设 `hypothesis_is_specific` 筛。这是工具自己掉进了「发现≠把问题精确化」的坑。
2. **【待 Q3，已解】finder 太通用 → 候选可迁移但不领域特异**：一句话压缩的 finder 只够触发"套路"。指向 Q3。
3. **【方法论局限】narrow 内联 = 单人单次，视角伪多样**：号称 N 个视角实际收敛到主 agent 一次的几个念头。结论：必须 wide 扇出才能公平评判。

**第二轮 wide 扇出回归**：两修复验证成功（强制假设生效；wide 多样性远胜 narrow，多个独立 agent 从不同组合**独立收敛到同一要害**——收敛≠雷同：narrow 的雷同是同一念头重复，wide 的收敛是多路径独立指向同一真信号），并暴露第 4 个缺陷：

4. **【已修】孤立式 select 在大批量下退化为辩护**。大批量候选 select 后近乎 0 淘汰——每个 select agent 只看一个候选、孤立评估，"对抗性怀疑"被执行成"论证它为何好"。
   → **修法（两阶段）**：① Stage 1 改"默认 kill、举证才留"，强制先写最致命反驳(禁止"无")+程序化兜底硬阈值（自评致命却放行/假设不具体/重要性<4 一律拦）；② 新增 Stage 2 横向 barrier，通看全部 survivor 去重合并+强制淘汰，最多留 `max(5,⌈n/3⌉)` 簇。已落地。

> **方法论沉淀**：凡是"逐项独立评估质量"的 LLM 筛选，都有"孤立辩护"退化风险——agent 看不到全局就倾向于给眼前这一个找理由通过。解法是**默认否决 + 强制证伪 + 一道能通看全局的 barrier**。这条可迁移到任何 generate→select 类工作流。

## 八、Q3 改造验证（厚 finder 受控 A/B，数据见 `test-logs.md`）

针对七.2 瓶颈做 Q3 改造：给 finder 补 move-by-move 厚轨迹(含**被否决分支**)，存于 `finder-traces.yaml`，内联进 `discovery-workflow.js` 的 `FINDERS[i].trace`。

**受控 A/B（隔离单一变量）**：同一 finder×范式 组合、同领域、同输入，唯一变量带不带厚轨迹。结果：带 trace 的产出从"换任何产品都成立的通用套路"变成"咬住领域特有结构 + 机制化（一个机制预测多个偏差）"，且学会了 trace 教的"先排除省事解释"。

**结论**：Q3 有效。**taste 的可迁移载体不是"结论"，而是"被否决分支"(大师排除了哪些更省事的解释)**——这条印证了 P21 默会知识"可知不可说"的边界：taste 本身传不了，但"淘汰错误答案的路径"可以传。已扩齐 8 个 finder 厚轨迹。
