# 思维范式诊断工具 (Thinking Patterns Diagnostic)

## Overview

这是一个"课题研究的元认知利器"：当你拿到任何命题、观点、研究课题时，本工具调用 21 个从跨学科大师身上提炼的"问题发现"元方法，帮你：

1. **去粗取精**：识别命题中真正关键的问题核心，剥离无关包装
2. **去伪存真**：暴露未经检验的隐含假设、伪问题、概念含混
3. **发现更好的问题**：通过换视角、换单位、换尺度，找到你原本没看到的切入口

## 三种模式：先判断用户要哪个

本工具有**三种结构上不同**的工作流，拿到任务先判断走哪条（共用同一套 21 范式引擎）：

| 模式 | 时机 | 触发信号 | I/O | 工作流 |
|------|------|---------|-----|--------|
| **诊断模式**（默认） | 行动前 | 用户已有一个命题/课题/观点，想批判、验证、找漏洞 | 命题 → 批判报告 | 本文件下方 Diagnostic Workflow |
| **发现模式** | 行动前 | 用户还没有命题，想在某领域「发现更好的问题」 | 领域+已知+好奇 → 候选问题 | 见 `discovery-mode.md`，可调 `discovery-workflow.js` |
| **伴随模式** | **行动中** | 用户在做研究的过程中撞到「意外/摩擦/不对劲」 | 一个意外 → 它是不是新问题的即时判断 | 见 `companion-mode.md`，半自动触发 |

> **判断窍门**：可被批判的句子→诊断；想钻进去找问题的领域→发现；做着做着冒出来的意外→伴随。模糊时用 AskUserQuestion 问清。
>
> **发现模式要点**：generate（生成性范式×finder母结构扇出，已用 Q3 厚轨迹增强领域特异性）→ select（两阶段：对抗式 kill + 横向去重）。穷尽式扇出需调 Workflow（多 agent，**须用户显式 opt-in**）；领域窄时内联挑 3-4 组合手跑。
>
> **伴随模式要点**：不靠用户主动调用，**Agent 在协助研究时主动识别意外信号**（"奇怪/不对劲/结果相反/又出现了/本来想…但发现"），识别到就轻提示"要不要记进 journal 并 triage"。triage 只跑三问：P02(噪声还是信号?)+P22(在重定义问题吗?)+P19(会不会是伪线索?)，60秒分流为升级/记录/存疑。状态存 `research-journal.md`(默认工作区级)。**宁可漏报不要误报打扰**。详见 `companion-mode.md`。
>
> **三模式闭环**：伴随(行动中捕意外)→升级→发现(领域生成候选)→候选→诊断(批判单命题)→带更锐利的问题回到行动。

## When to Use This Skill

- 审视一个研究课题是否是"好问题"（诊断）
- 对任何命题/观点做批判性分析（诊断）
- 在一个领域里从零生成候选问题（发现）
- 从一个模糊想法中提炼出可攻克的具体问题（诊断/发现皆可）
- 对商业/产品/战略命题做深层假设检验（诊断）
- 选题阶段评估多个候选方向（诊断）
- 对"理所当然"的现状产生警觉（诊断）
- 研究过程中撞到意外/数据不对劲/计划被打断时，判断它是不是在指向更好的问题（伴随）

## Diagnostic Workflow

### 前置检查: 开放模式（所有范式的隐含前提）

> 来自 John Cleese 对 MacKinnon 创造力研究的总结：人有两种工作模式，**封闭模式**(聚焦、有目的、轻微焦虑、赶着完成)和**开放模式**(放松、宽广、无目的、可玩耍)。Fleming 发现青霉素的关键不是聪明，而是他当时在开放模式——"在封闭模式下，一个长不出菌的培养皿是无关的废物；在开放模式下，它是一条线索。"

**这条对本工具至关重要**：后续 21 个范式（尤其 P02 异常驱动、P09 无知地图）只有在开放模式下才会真正触发。封闭模式下，异常被当噪声扔掉、盲区被绕开。

诊断开始前，先判断并提示用户：

- 如果用户是在"赶着要答案、要快速结论"的封闭状态 → 提醒：本工具的产出是"更好的问题"而非"立刻的答案"，请先给自己一点不评判、不急于收敛的空间。
- 诊断过程中**不要过早收敛**：Cleese 的另一发现是，最有原创性的人会在找到第一个"够用"的答案后，仍多停留一会儿，逼出更原创的解。本工具同理——不要满足于命题的第一层假设。

### Phase 0: 接收命题

接收用户输入的命题。可以是：

- 一个研究课题（如"大语言模型的涌现能力机制"）
- 一个商业问题（如"如何提升用户留存"）
- 一个观点/主张（如"AI 将在 5 年内取代大部分白领工作"）
- 一个模糊想法（如"我想研究注意力"）

如果命题过于模糊，用 AskUserQuestion 要求用户补充：你的目标是什么？是想验证它、质疑它、还是找到更好的问题？

### Phase 1: 快速扫描——匹配适用范式

不需要全部 21 个都跑。根据命题特征匹配 3-5 个最适用的范式：

| 信号 | 优先召唤 |
| --- | --- |
| 命题中有"人人默认"的概念 | P01 基础假设质疑 |
| 有被忽略的异常/反例 | P02 异常驱动 |
| 结论依赖类比或先例而非底层事实 | P03 第一性原理 |
| 另一个领域有同构成熟理论 | P04 跨域结构类比 |
| 关键变量可推到极端来检验 | P05 极限推演 |
| 怀疑分析对象的颗粒度/层级选错了 | P06 重新定义分析单元 |
| 无法做真实实验但可推演 | P07 反事实/思想实验 |
| 核心概念模糊、无法判断真假 | P08 概念操作化 |
| 领域看似成熟，可能有隐藏盲区 | P09 无知地图 |
| 存在两个都对但互相矛盾的事实 | P10 矛盾并置 |
| 正向追问陷入死胡同 | P11 逆向提问 |
| 某个"自然"分类/制度从未被追问来历 | P12 谱系溯源 |
| 现象在当前尺度上噪声/平凡 | P13 尺度跃迁 |
| 怎么优化都不动，怀疑没打在瓶颈上 | P14 约束识别 |
| 想沿一条信念主线持续生成问题 / 现状违反某条你看重的原则 | P15 原则驱动扫描 |
| 命题看起来重要、攻法似有，但你隐约不安想先排雷 | P19 死胡同剖析 |
| 现象高度依赖语境/相互作用，"孤立变量"分析反复失效 | P16 关系/情境思维 |
| 对象每次正面定义都会扭曲/崩塌，"不是什么"比"是什么"更清晰 | P17 否定式逼近 |
| 问题在行动前无法充分定义，只有动手才能发现真正的问题是什么 | P22 行动中反思 |

#### 领域先验：按命题所属领域调整范式优先级

基于知识库 321 篇大师著作的实证统计(`works/`)，不同领域的"问题发现"有各自的优势招式。当命题明显属于某领域时，**在信号匹配之外，额外优先尝试该领域的高频范式**：

| 命题领域 | 优先范式(实证Top) | 直觉解读 |
| --- | --- | --- |
| 数学/形式/逻辑 | **P06换单元** · P01 · P08 | 靠"换研究对象/表征"开路 |
| CS/AI/信息技术 | **P04类比** · P06 · P02 · P08 | 借成熟领域结构 + 把模糊能力操作化 |
| 生命/生物/医学 | P01 · P06 · **P04** · P02 | 借结构(进化/信息论) + 抓异常 |
| 神经/认知科学 | **P06换分析层级** · P08 · P04 · P10 | 在计算/算法/实现三层间切换，借物理数学结构 |
| 物理/化学/材料 | **P08操作化** · P03第一性 · P07 · P10 | 把谜题变成可测量/可计算 |
| 心理学/行为科学 | **P01质疑理性假设** · P02异常 · P07 · P08 | 每个发现都是把"人的某个默认能力"作为可被实验击穿的靶子 |
| 经济/商业/制度 | **P01质疑前提** · P06 · P07思想实验 · P10 | 拆掉关于人/市场/制度的默认假设 |
| 社会/政治/文化 | P01 · P06 · **P12谱系溯源** · P13尺度 | 把"理所当然的社会事实"陌生化 |
| 人文/历史/哲学 | P01 · **P12谱系** · P17否定式 · P06 | 把"天经地义"还原为历史产物，或拒绝正面定义 |
| 设计/创业/实践 | **P22行动中反思** · P08 · P15原则 | 问题在做的过程中才浮现；原型是提问工具 |
| 医学/公共卫生/临床 | **P08操作化** · P02异常驱动 · P19死胡同 | 把"病因是什么"变成可重复验证的程序；坚持追定量异常 |
| 管理/组织/战略 | **P06换分析单元** · P01质疑前提 · P02异常 | 德鲁克/戴明/克里斯坦森都是换了分析单位才看到真问题 |

> **全库最高频两招**：P01(质疑默认前提) 与 P06(重新定义分析单元)。任何命题都值得先问这两个——它们覆盖了大师问题发现的绝大多数。

#### 跨域问题发现者(可选增强)

若命题需要打破学科壁垒、或卡在单一领域视角，可调用知识库中的"跨域问题发现者"作类比佐证(见 `cross-domain-index.yaml`)：冯·诺依曼(公理化+极限)、西蒙(有限理性)、图灵(操作化)、卡尼曼(质疑理性假设)等——他们的共性是拥有一个可跨域迁移的"母结构"。可启发用户："你的命题能不能借用另一个领域已经成熟的结构来重新提问？"

### Phase 2: 深度诊断——逐范式跑诊断提问

对每个匹配的范式：

1. **说明为何这个范式被触发**（用户命题中的哪个信号）
2. **跑 diagnostic_questions**：把范式的诊断提问逐一套用在用户命题上，给出具体分析
3. **给出该范式视角下的洞察**：命题的隐含假设是什么 / 被忽略的是什么 / 更好的问题在哪

### Phase 3: 综合诊断报告

输出结构化报告，包含以下模块：

#### 3.1 隐含假设清单

命题默认了哪些未经检验的前提？逐条列出，标注"已验证/未验证/争议中"。

#### 3.2 被忽略的问题

通过范式诊断发现的、比原命题更值得追问的问题（通常 2-4 个）。每个标注：

- 来自哪个范式的诊断
- 为何比原命题更有价值（可解性 × 重要性 × 被忽略性）

#### 3.3 重构建议

如果原命题需要重新表述（换切入口/换单位/收窄范围），给出 1-2 个重构后的命题形式。

#### 3.4 风险提醒

诊断可能的失败模式——哪些范式可能被误用、哪些结论不宜过度外推。

### Phase 4（可选）: 深挖单个方向

如果用户对某个范式的诊断结果特别感兴趣，可以展开：

- 补充跨学科案例佐证
- 把发现的新问题进一步用其他范式交叉验证
- 设计验证路径（如何检验你的新假设）

## Core Principles

1. **不要替代用户做判断**——工具的产出是"更好的问题"，而非"正确的答案"。
2. **敢于说"这可能就是个好问题"**——如果原命题已经很好，不为诊断而诊断，直接说明它好在哪。
3. **范式之间互设 counter_pattern**——用完一个范式后，主动检查其对立范式是否也有话要说，避免单一视角。
4. **引用跨学科先例**——每条洞察尽量附上一个历史上类似结构的经典案例，增强说服力。
5. **承认局限**——明确标注哪些判断基于"经典共识"而非一手史料，哪些需要进一步验证。

## 范式详细定义（供执行时参考）

以下为 21 个范式的完整 diagnostic_questions，执行诊断时直接引用。

### P01 基础假设质疑 (Assumption Excavation)

- 这个命题里，哪个词/概念是大家默认共享、却从没人精确定义的？
- 如果我拒绝接受这个前提，论证会在哪一步崩塌？崩塌处就是新问题。
- 这个"常识"是观测到的事实，还是从未验证的习惯性假设？
- 把这个前提换成它的反面，世界会变成什么样、能否被观测到？

### P02 异常驱动 (Anomaly-Driven Inquiry)

- 这里有没有一个被解释为'误差/特例/巧合'、但反复出现的东西？
- 如果这个异常是真的而非噪声，现有理论的哪一块必须让位？
- 大家忽略它，是因为它真不重要，还是因为它无法被现有框架容纳？
- 历史上这个量级的'小偏差'有没有曾经撑开过新理论？

### P03 第一性原理 (First-Principles Decomposition)

- 这个结论是从底层约束推出来的，还是只因为'一直都这么做'？
- 拆到不能再拆，最底层真正限制它的物理/逻辑事实是什么？
- 如果今天从零开始、不受历史方案束缚，会怎么搭？
- 现状与从底层重建的方案之间的差，是必然的还是历史惰性？

### P04 跨域结构类比 (Cross-Domain Analogy)

- 把这个问题抽象成'实体+关系+驱动力'，它的骨架像哪个我已经懂的系统？
- 那个成熟领域里已被回答的问题，对应到这里是什么问题？
- 类比在哪里成立、在哪里断裂？断裂点是噪声还是真正的领域特异性？
- 我是在迁移'深层结构'，还是只是表面措辞的相似？

### P05 极限与边界推演 (Limiting-Case Reasoning)

- 如果把这个变量调到 0 或无穷大，命题会变成什么样？
- 在最理想/最极端的情形下，本来纠缠的因素哪些会消失、哪些会凸显？
- 现有理论在边界处会不会给出荒谬结果(发散/矛盾)？荒谬处即漏洞。
- 现实与理想极限之间的差距，本身是不是一个更值得研究的问题？

### P06 重新定义分析单元 (Reframing the Unit of Analysis)

- 我现在默认的'一个基本单位'是什么？它真的是自然的接缝吗？
- 如果把单位换成更大/更小/完全不同的东西，什么新问题会冒出来？
- 当前的无解，是问题本身难，还是因为切分世界的颗粒度选错了？
- 现象发生的真正层级，和我正在分析的层级，是同一个吗？

### P07 反事实与思想实验 (Counterfactual & Gedankenexperiment)

- 有没有一个现实做不到、但思想上可以推演的情形，能逼出这个理论的矛盾？
- 在这个假想情形里，我必须额外承认哪条没明说的前提才能自圆其说？
- 如果改变一个我以为无关紧要的条件，结论会不会反转？
- 这个思想实验暴露的是真矛盾，还是我设定里偷偷塞进的漏洞？

### P08 概念操作化 (Operationalization)

- 这个命题里最含糊的概念，能用什么可观测的指标或程序来代理？
- 怎样的结果会判定它为假？如果无法证伪，它还是不是一个真问题？
- 我的操作化抓住了原概念的核心，还是只抓住了易测但无关的替身？
- 把抽象争论换成'设计一个能区分两种情形的测试'，该怎么设计？

### P09 无知地图 (Mapping Ignorance)

- 在这个领域，哪些问题是大家'默契地绕开、从不正面问'的？
- 现有的成熟，是真的解决了，还是只解决了容易测的那部分？
- 如果有一种现在还没有的工具/概念，会冒出哪些今天问不出的问题？
- 我列出的'未知'，是真空白，还是只是我个人没读到？

### P10 矛盾并置 (Holding Contradictions)

- 我手上有没有两个都对、却互相矛盾的事实？矛盾发生在什么交界面？
- 我是不是为了舒服，过早地偏废了其中一方？
- 让两者都成立，需要一个怎样的更大框架？
- 这道裂缝历史上是否曾是重大突破的入口？

### P11 逆向提问 (Inversion)

- 把问题反过来：怎样做才会百分百搞砸？答案里藏着真正的关键。
- 不问'为什么是现在这样'，而问'为什么偏偏不是其它本可能的样子'？
- 要让这件事彻底不发生，必须满足什么？那就是它的命门。
- 我执着于追求成功路径，是不是其实'避开失败'才是主要矛盾？

### P12 谱系溯源与陌生化 (Genealogy & Defamiliarization)

- 这个我视为天经地义的东西，是什么时候、被谁、为了什么造出来的？
- 在别的文化/历史/路径里，它是不是长得完全不同？
- 把它当成陌生外星现象来看，哪些'理所当然'立刻变得需要解释？
- 它的'自然化'遮蔽了哪些原本可见的问题或受损者？

### P13 尺度跃迁 (Scale Shifting)

- 把时间/空间尺度放大或缩小几个数量级，这个现象会变成什么样？
- 在哪个尺度上它像噪声，在哪个尺度上它显出规律？
- 整体在某尺度上的性质，能否由更小尺度的部分推出？不能之处即新问题。
- 我是不是恰好卡在一个'什么都看不清'的中间尺度？

### P14 约束识别 (Constraint Hunting)

- 在所有影响因素里，哪一个一旦解除、整个系统立刻就能往前走？
- 我是不是在拼命优化一个根本不是瓶颈的环节？
- 真正的限制是技术的、还是资源/协调/认知的？(瓶颈常不在你盯着的地方)
- 当前的多处努力，哪些其实对全局产出毫无影响？

### P15 原则驱动扫描 (Principle-Driven Scanning)

- 我真正相信的、能用来评判好坏的那条原则是什么？(若说不出，先把它逼出来)
- 用这条原则扫描现状，哪里明显违反了它、却被大家当作理所当然？
- 这个违反之处，是该被修复的真问题，还是原则本身需要修正？
- 我是在追逐零散热点，还是在沿一条原则主线持续生成问题？

### P19 死胡同剖析 (Dead-End / Failure Autopsy)

- 历史上有没有一个结构跟我这命题很像、当年也被当成好问题、最后却是伪问题的案例？
- 我的命题之所以"看起来重要"，会不会恰恰诱导我高估了证据(像冷聚变)？
- 我依赖的核心前提，是被验证过的事实，还是一个像"以太需介质"那样无人质疑的类比？
- 若这是死胡同，最可能的死法：错类比/反方向/观察者偏差/工具赝象/打补丁救错框架/禁区主张/真伪混杂？

### P16 关系/情境思维 (Relational / Contextual Framing)

- 我是不是默认了"这个对象可以从它的背景与关系里干净地切出来单独研究"？
- 这个对象的关键性质，有多少是它"自身固有的"，有多少是"由关系决定的"？
- 如果把研究单位从"个体"换成"个体所处的关系格局"，什么新问题会浮现？
- 现在的失衡，是某个孤立部分坏了，还是关系网络本身错配了？(比P06更根本——质疑'对象可被孤立'本身)

### P17 否定式逼近 (Apophatic / Via Negativa)

- 我有没有一直追求"正面的最终定义"，而这个定义每次都塌掉？
- 把问题倒过来：我能确定这个对象【不是】什么？先把"不是"清单列满。
- 如果正面定义必然扭曲对象，那么"它不是X/Y/Z"这张排除清单本身是不是答案？
- 这里的"不知道"，是认识论上真实的极限，还是我还没找到正确的正面框架？(波普尔式可证伪/塔勒布式减法)

### P22 行动中反思 (Reflection-in-Action)

- 我是不是假设必须想清楚问题才能开始？能不能先做一个最小的动作来检验我的问题假设？
- 我在实践中遇到的"出乎意料"，有没有在重新定义问题本身？(那才是真正的问题)
- 我现在做的原型/草稿/初版，是在展示答案，还是在探索真正的问题是什么？
- 我说的"这个问题的解决方案"，里面有多少其实是对问题本身未经验证的假设？
