# 达人稿件图片审核

用视觉模型审核达人稿件中的图片，输出结构化评分与逐图修改建议。

## 何时使用

**合适的场景：**
- 达人稿件/内容中的图片审核（ma-draft-review 调用）
- 图文、封面、产品图的质量与品牌露出检查

**不合适的场景：**
- 纯文字审核 → 用 `ma-content-audit`
- 视频画面审核（当前不覆盖）

## 调用协议

**输入**（由调用方提供）：
- 图片列表（按顺序编号，如 图1、图2…）
- 品牌与产品信息（用于判断品牌露出与契合度）
- brief 内容方向（用于判断图片是否贴合，如场景/叙事/氛围点要求）
- brief 中与画面相关的视觉要求（可选）

**输出**：JSON，供调用方组装为最终回复：

```json
{
  "image_score": 50,
  "images": [
    {
      "index": 1,
      "text_in_image": "图片内文字原文（标题/贴纸/字幕/包装/角标，无则空；供产品名逐字核对留证）",
      "issues": [
        { "issue": "三张图重复同质化", "suggestion": "换不同场景/角度", "severity": "critical" },
        { "issue": "无品牌露出", "suggestion": "补一张带品牌盒的图", "severity": "critical" }
      ]
    }
  ],
  "overall_issues": [
    { "location": "图片1/图片2", "issue": "问题描述", "suggestion": "修改建议", "severity": "critical | warning" }
  ],
  "has_critical": false
}
```

- `image_score` 取各图最低分或整体观感分（0-100，**内部参考**，不用于调用方红黄判定）
- `severity`：**critical = 硬伤**（合规违禁 / 品牌露出完全缺失 / 构图大面积同质化 / 画面不可用 / 明显偏离 brief 硬性产品信息 / 竞争性他品牌 Logo 主体露出）；**warning = 建议**（轻微瑕疵、可能优化点，含 brief 建议层场景/三图/首图等未达但不构成硬伤），缺省 warning
- `has_critical`：任一 overall_issues 为 critical 时为 true；调用方（ma-draft-review）据此判红卡
- `text_in_image`：逐图输出图片内可读文字原文（无则空字符串），调用方据此核对产品名是否准确；文字模糊时标注 `"（模糊不可辨）"`
- `overall_issues` 合并逐图问题，`location` 用 `图片N` 锚点，与 ma-draft-review 修改意见的 `[图片N]` 对应

## 工作流

### Step 1 · 配置检查
用 `KIMI_API_KEY` + OpenAI 兼容协议调 Kimi 多模态模型，**优先 `kimi-k2.6` / `kimi-k2.5`**（原生多模态，支持 `image_url` base64 直传；`KIMI_MODEL` 可覆盖，保守兜底 `moonshot-v1-8k-vision-preview`，`KIMI_BASE_URL` 默认 `https://api.moonshot.cn/v1`）。也可用 MAPro 渠道配置的 OpenAI 兼容多模态模型——图片已作为多模态附件随消息注入（image_url base64），渠道模型需支持视觉输入（如 kimi-k2.6 / kimi-k2.5）。未配置或调用失败 → 返回 `{ "image_score": null, "has_critical": false, "error": "Kimi 未配置" }`，由调用方降级为纯文字审核。

### Step 2 · 逐图审核

每张图按以下维度检查：

| 维度 | 检查要点 |
|------|---------|
| 贴合 brief | 图片整体内容方向是否贴合 brief（场景/叙事/氛围点，如 brief 要求居家氛围却拍办公室硬照） |
| 三图结构 | 是否包含三种必备图：场景图（与产品相关的氛围感场景）、产品放大特写图、产品整体图 |
| 场景氛围 | 场景是否贴合品牌调性（如居家/外出/办公） |
| 产品特写 | 产品是否清晰、突出卖点 |
| 构图重复 | 多图间是否同质化（角度/场景/内容重复） |
| 摆拍痕迹 | 是否过度摆拍、不自然 |
| 品牌露出 | 品牌/产品名是否露出（logo、包装、标签） |
| 图片内文字/配字 | 标题/贴纸/字幕/包装/角标中的产品名是否与传入产品池一致（**逐字读字核对**，不得靠猜） |
| 画面质量 | 清晰度、光线、构图美观 |
| 合规 | 违禁内容、虚假宣传、敏感画面 |

### Step 3 · 输出
每张图列出问题与建议并标注 `severity`，合并为 `overall_issues`，给出 `image_score`（内部参考）与 `has_critical`。

## 规则

1. **贴合 brief（分级）**：整体内容明显偏离 brief **硬性产品信息**（产品/卖点/合规）→ critical；轻微不贴合 → warning；仅偏离 brief 建议层场景/氛围（如"桌面对决"改用其他合理生活场景）→ warning"可优化"，不得 critical
2. **三图结构（按 brief 拍摄建议）**：场景图/产品放大特写图/产品整体图三种，brief 明文"必须"时缺任一种 → critical；brief 未明确"必须"时按建议层 → warning"可优化"，明确缺失类型与建议补齐的 `图片N`；**首图/封面构图、产品占比、达人自拍占比、拼贴风格属拍摄建议层 → 一律 warning，即使 brief 写明"首图必须露出产品全貌"也不得 critical**
3. **品牌露出是核心**：关键场景无品牌/产品露出（logo/包装/标签）→ critical；仅品牌名在话题标签、正文未露出 → warning"可优化"，不判 critical
4. **构图重复**：多图大面积同质化标 critical，必须明确指出"第几张与第几张重复"；轻微重复标 warning
5. **画面不可用即 critical**：模糊、过暗、构图失衡到无法使用的图片，标 critical 并给出重拍方向
6. **合规一票否决（他品牌Logo限定）**：违禁画面、虚假宣传画面 → critical，`has_critical` = true；**他品牌 Logo 仅当属于同类竞品（水果生鲜/果切/外卖等）且占据画面主体时才 critical**——非竞品品牌（地铁/街道/商场广告牌如 SUBWAY、路人穿搭、店铺招牌、其他商品）**即使占据较大画面**也 → warning"可优化"（建议裁剪或换角度），不判 critical
7. **品种辨认类不标 critical**：水果品种/材质/真假等**需人工核对实物**的判断，图片审核**不得标 critical**（不得仅凭图片下红卡），一律标 warning"需人工核对实物"，由调用方（ma-draft-review）降为黄卡 @Account 拍板
8. **建议可操作**：每条问题附具体改法（"换不同场景/角度""补一张带品牌盒的图""补一张产品整体图"）
9. **图片顺序稳定**：`图片N` 的编号与调用方传入顺序一致，不得重排
10. **真实感优先**：达人自拍主导、日常/通勤/生活化场景、广告感弱的图片不标 critical（最多 warning）；不要求每张图都是产品硬广画面，仅图片虚假宣传、产品信息错误或品牌露出完全缺失时方可 critical
11. **图片配字产品名不准确 → critical（强制）**：图片内文字（标题/贴纸/字幕/包装/角标）中的产品名，归一化后仍不能对应到调用方传入的产品池 → critical，`location` 写 `图片N`，`suggestion` 给出正确产品名；词序倒换/同义变体不算不准确（warning）；文字模糊无法辨认 → warning“需人工核对图片文字”，不得凭猜测判 critical
