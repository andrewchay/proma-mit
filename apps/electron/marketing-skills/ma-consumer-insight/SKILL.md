# 消费者洞察（Consumer Insight）提炼

## 这个 Skill 做什么

基于用户画像、搜索习惯、市场与竞品信息，提炼可用于传播的消费者洞察：
- **观察（Observation）**：用户行为/言论中可验证的现象
- **洞察（Insight）**：现象背后的动机、冲突或人性真相
- **张力（Tension）**：洞察中存在的矛盾或张力
- **传播切入点（Entry Point）**：基于洞察的创意/传播入口
- **购买任务（Job to be Done）**：用任务视角重述洞察——用户不是在"买产品"，而是在特定情境下"雇一个进步"；每个洞察必须能翻译成购买任务

参考 JWT TTB 的洞察标准：**洞察不是观察，而是对"为什么"的深层理解**；任务定义（JTBD）：**"特定情境下想取得的进步"，必含功能、社会、情感三个维度**。

## 何时使用

**合适的场景：**
- 品牌策略制定前的洞察提炼
- 创意概念发想前的 Insight 输入
- 比稿/提案中的消费者理解部分
- 用户画像已完整，但需要提炼传播角度时
- 发现数据矛盾或用户言行不一，需要解释"为什么"时

**不合适的场景：**
- 没有用户画像或市场信息时（洞察缺乏依据）
- 纯执行层面的单次内容创作
- 已经有明确 Big Idea，只需细化脚本时

## 工作流

### Step 1 · 输入确认

确认以下信息是否充足：
| 信息项 | 说明 |
|--------|------|
| TA 画像 | 人口统计、心理特征、消费行为 |
| 搜索习惯 | 平台、场景、关键词 |
| 市场/品类信息 | 品类趋势、痛点、机会点 |
| 竞品传播 | 竞品在说什么、回避了什么 |
| 品牌信息 | 品牌 DNA、品牌主张、品牌人格 |

### Step 2 · 观察收集

列出 3-5 个可验证的用户行为或言论现象，例如：
- "25-35 岁女性在小红书搜索'通勤穿搭'时，频繁收藏'高级感'笔记"
- "评论区高频出现'好看但不日常'的反馈"

优先关注五类信息量最大的"猎场"：用户自己的生活、**非消费**（该进步目前靠"不做"来对付，如"干脆不办卡了"）、**变通行为**（workaround，如用鞋盒装收据）、**人们不想做的事**（负面任务）、产品的**非常规用法**（NyQuil 被当助眠药）。

### Step 3 · 洞察提炼

从观察中提炼 Insight，要求：
- 回答"为什么"，而不是"是什么"
- 包含人性冲突或张力
- 能够自然连接到品牌角色

### Step 4 · 任务视角检验（JTBD，必做）

把每个候选洞察重述为购买任务句式：**"当 __（情境）__ 时，我想要 __（动机/进步）__，好让我 __（社会/情感收益）__"**，并过三道检验：

1. **情境检验**：任务必须带具体情境；"方便""高级"这类形容词不是任务，是体验
2. **跨品类可雇佣性检验**：如果解决方案只能来自本品类，那是技术规格不是任务（"想要一杯奶昔"不是任务；"让漫长无聊的通勤提神且不饿"才是——香蕉、百吉饼都能应聘）
3. **竞争重画检验**：列出任务视角下的真实竞争集——包括跨品类对手（Netflix 的对手是"一切放松方式"）和**非消费**（Airbnb 约 40% 客人原本"根本不出行"）；据此判断品牌真正的对手和增长空间

补充：雇佣是双重事件——**购买（Big Hire）≠ 使用（Little Hire）**；用户"雇"新方案前必须先"解雇"旧方案，转换受四力撕扯（处境推力、新方案拉力 vs 习惯、对新事物的焦虑）。洞察若涉及习惯类品类，需说明"用户要先解雇什么、焦虑怎么消除"。

### Step 5 · 切入点输出

基于 Insight 与购买任务，输出可传播的 Entry Point。

## 输出格式

必须以 JSON 格式返回：

```json
{
  "status": "complete | partial",
  "observations": [
    {
      "source": "数据来源，如：小红书搜索'通勤穿搭'前20条笔记",
      "behavior": "观察到的现象",
      "evidence": "支持该观察的具体证据"
    }
  ],
  "consumer_insight": {
    "statement": "一句话洞察",
    "tension": "冲突/张力",
    "human_truth": "背后的人性真相",
    "brand_connection": "品牌如何回应这个洞察"
  },
  "purchase_job": {
    "statement": "当（情境）时，我想要（动机/进步），好让我（社会/情感收益）",
    "functional_dimension": "功能维度",
    "social_dimension": "社会维度",
    "emotional_dimension": "情感维度",
    "real_competitors": ["任务视角下的跨品类对手1", "对手2"],
    "nonconsumption_rival": "非消费对手，如：干脆不做/不买",
    "fire_hires": "用户要先解雇的旧方案及其焦虑（涉及习惯类品类时必填）"
  },
  "entry_points": [
    {
      "angle": "传播角度",
      "rationale": "为什么这个角度能切入",
      "platform_fit": ["适合平台1", "适合平台2"]
    }
  ],
  "confidence_score": 85,
  "missing_info": ["若有缺失信息，在此列出"]
}
```

## 规则

1. **insight 必须带张力**：体现用户内心的冲突，如"想要专业表现，也在意风格表达"
2. **observation 必须有证据**：不是主观感受，要引用具体数据来源或行为
3. **human_truth 要普世**：超越具体产品，触及更广泛的人性动机
4. **brand_connection 必须自然**：不是强行关联，而是品牌恰好能回应这个冲突
5. **entry_point 必须可执行**：创意团队能据此直接发想内容和文案
6. 如果没有足够信息，**status** 标记为 `partial` 并列出 **missing_info**
7. **confidence_score** 基于信息充分程度诚实打分（0-100）
8. **purchase_job.statement 必须带情境**：没有情境的任务不是任务（"我想变美"不合格，"周一早会前 10 分钟想看起来气色好"合格）
9. **过不了跨品类可雇佣性检验的洞察要降级**：解决方案只能来自本品类时，说明洞察停在产品层，回 Step 3 重挖动机层
10. **real_competitors 必须至少一个跨品类或非消费对手**：只列同品类竞品说明竞争重画没做，品牌传播会困在零和份额思维里
