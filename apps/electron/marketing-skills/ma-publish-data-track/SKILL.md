# 达人发布数据追踪

## 这个 Skill 做什么

追踪达人内容发布后的数据表现：

1. **发布记录**：群内"发布 + 小红书链接" → 记录达人/链接/时间到发布台账
2. **数据对号入座**：群内报数（赞/评论/播放）→ 自动关联最近发布记录 → 与阈值比较 → 异常预警
3. **发布后查数**：发布到期后（默认 24h），用 CDP 爬虫复用 ma-kol-scraper 方法论按 noteId 抓取笔记真实曝光/点赞/评论/收藏数据 → 回写台账 → 异常预警

## 何时使用

**✅ 触发（群消息中出现以下任意特征）**
- 发布完成："发布 / 上线 / 发出 / 已发" + 小红书链接（注意排除"发布预览"，那是待审核提交）
- 数据汇报："数据 / 赞 / 评论 / 播放 / 流量 / 曝光 / 阅读" + 数字或负面语气（才/只/没跑起来/数据差/凉了/扑街）

**❌ 不触发**
- 稿件审核（初稿/改稿/请查收）→ 用 `ma-draft-review`
- 纯闲聊、无数字无指标词的消息（如"数据不错"不报）

## 发布台账

存储：`workspace-files/publish-ledger.jsonl`（JSONL 追加，字段：达人名/链接/发布时间/发布消息ID/发送人）

记录规则：
- 达人名提取同 ma-draft-review：优先 `【XX】`，否则紧邻发布/上线的 2-12 字 token
- 链接用严格 URL 字符集提取（不含尾随中文/标点），支持 xhslink.cn 短链和小红书完整链接

## 群内报数 · 数据对号入座

### Step 1 · 解析报数

用正则从消息中提取 `(数字)(万|千)?(个)?(指标词)`，如"300赞"、"1.2万赞"、"13个赞"。中文数字归一化（俩=2、几=1）。

| 指标词 | 映射 |
|--------|------|
| 赞 | likes |
| 评论 | comments |
| 播放/浏览/观看/阅读/曝光/流量 | play |

### Step 2 · 判定异常

阈值（可按 campaign 调整，默认）：赞 < 100 / 评论 < 30 / 播放 < 5000

| 情况 | 判定 |
|------|------|
| 指标词+数字 < 阈值 | 🚨 异常 |
| 指标词+数字达标但语气负面（才/只/凉了等） | 🚨 异常（数据可能有问题） |
| 达标且语气正常 | ✅ 正常 |
| 无指标词无数字（如"数据不错"） | 不判定，静默 |

### Step 3 · 关联发布记录

- 优先按达人名匹配最近的发布记录
- 无达人名则取群内最近一条发布记录
- 回复带"关联发布：{达人}（发布于 MM-DD HH:MM）"

### Step 4 · 预警回复

- 异常 → 📊 数据异常卡片（yellow），@我方关键人，内容含：关联发布 + 指标值 + 异常原因 + 建议
- 正常 → 不回复（静默）或简短确认

## 发布后查数（CDP 爬虫，复用 ma-kol-scraper 方法论）

### 抓数脚本

基于 ma-kol-scraper 的 [kol_collector.py](file:///Users/xuxuwen/mapro/apps/electron/default-skills/ma-kol-scraper/scripts/kol_collector.py) 的 CDP 方法论，写一个轻量 `note_data_fetcher.py` 放在本 skill 的 `references/` 下，按 noteId 抓取单条笔记数据。

**复用三件套**（从 kol_collector.py 移植）：
1. `_init_browser`：`connect_over_cdp("http://127.0.0.1:9222")` + 登录态检查 + 页面复用
2. `on("response")` 捕获蒲公英/小红书笔记数据 API
3. 连接中断自动重连（`_is_conn_lost`）

**区别**：kol_collector 按 `userId` 批量采博主笔记；本脚本按 **noteId** 打开蒲公英笔记数据页抓单条笔记的曝光/阅读/点赞/收藏/评论。

输入：小红书链接/xhslink 或 noteId → 输出：`{exposure, reads, likes, comments, favorites}`。

### 查数流程

1. 发布记录到期（默认发布后 24h）→ 从台账取链接
2. 调 `note_data_fetcher.py` 抓数（需 Chrome 已开 CDP + 蒲公英登录态）
3. 数据源不可用（CDP 未开 / 未登录 / 脚本失败）→ 跳过本轮，保留台账待下轮重试，不误报
4. 抓取成功 → 回写台账 `data_checked_at` + 各项指标
5. 赞 < 阈值 → 📊 数据异常卡片："达人：{达人}（发布后 24h）\n赞 X / 评论 Y / 播放 Z\n赞低于阈值，自然流基本定型，建议关注/优化"

## 关键配置

| 配置 | 说明 |
|------|------|
| 数据阈值 | 赞 < 100 / 评论 < 30 / 播放 < 5000（可按 campaign 调整） |
| 首次查数时间 | 发布后 24h（`DATA_CHECK_AFTER_HOURS`） |
| CDP 端口 | 9222（与 ma-kol-scraper 一致） |
| 台账 | `workspace-files/publish-ledger.jsonl` |

## 与相关 Skill 的边界

- `ma-draft-review`：只管审稿（稿件三态 + brief 匹配），不管发布后数据
- `ma-kol-scraper`：选人阶段（蒲公英批量采集达人 → CSV → 评分卡）；本 skill 是投放执行阶段（发布后单条笔记数据追踪），**复用其 CDP 爬虫方法论**但不共享触发词
- `ma-campaign-growth-optimizer`：数据异常后的内容/达人/人群优化分析，本 skill 只预警不分析
