# AI 员工能力演化运维手册

> 适用范围：Gravitas AI 员工受控能力演化（版本、样本、评测、审批、观察、回滚、Canary、建议、台账、导出）。
> 本文描述**已经实现**的能力与**明确未实现**的边界，不把设计意图当作已交付功能。

## 1. 能力全貌

| 环节 | 位置 | 说明 |
|---|---|---|
| 学习样本 | AI 员工卡片 → 能力版本与学习样本 | 执行完成/失败/取消后自动生成 `pending` 样本 |
| 人工审核 | 同上 | 编辑脱敏摘要后标记为 `sanitized`，或永久 `excluded` |
| 受控评测 | AI 员工卡片 → 受控评测并生成候选 | 只用 `sanitized` 样本；真实调用模型；会产生费用 |
| 候选审批 | Proactive → 审批 | 展示 scope、父版本、训练/held-out 分数、样本数、内容 hash |
| 版本观察 | AI 员工卡片 → 能力演化 | 按执行冻结版本归因，30 天窗口 |
| 人工回滚 | 同上 | 必填原因，事务化，写入不可变审计 |
| Canary | 治理配置与接口 | 默认关闭，按任务稳定分流，只暂停不自动回滚 |
| 建议扫描 | Proactive → 今天 | 只建议，需人工触发评测 |
| 台账与复盘 | 治理接口 | 只读报告，不含样本正文与路径 |
| 导出导入 | 治理接口 | 默认脱敏导出；导入仅校验并展示摘要 |

## 2. 数据位置

| 数据 | 位置 |
|---|---|
| 版本、样本、审计、执行 | 项目 SQLite（`~/.gravitas/projects/`） |
| 治理策略与变更审计 | Proactive 配置目录下的 `employee-capability-governance.json` |
| Canary 配置 | Proactive 配置目录下的 `employee-capability-canary.json` |
| 建议扫描状态 | Proactive 配置目录下的 `employee-capability-scans.json` |
| 评测 benchmark 与 scoreboard | eval 目录（`<config>/eval/benchmarks/`） |

## 3. 常见运维场景

### 3.1 版本表现变差

1. 打开 AI 员工卡片 → 能力演化，查看 active 版本的健康指标（返工率、失败率、已判定样本量）。
2. 若提示"样本量不足"，先积累样本，不要据此下结论。
3. 确认需要回退时：点击"回滚到父版本/基线"，填写原因，确认执行。
4. 回滚只影响**后续**任务；已完成的执行保持原冻结版本。

### 3.2 样本审核积压

- `pending` 样本不参与评测。必须人工编辑摘要后标记 `sanitized`。
- 摘要中不得包含绝对路径、会话原文、密钥或附件内容。
- 明确不具参考价值的样本使用"排除"，该操作不可逆。

### 3.3 评测未生成候选

按返回状态判断原因：

| 状态 | 含义 | 处理 |
|---|---|---|
| `judge_not_independent` | 评判者与被评方同源 | 配置独立评判渠道或模型 |
| `held_out_regression` | held-out 分数下降 | 候选被拒；检查样本分布或放弃该候选 |
| `no_accepted_candidate` | 无严格提升 | 样本可能不足或已达瓶颈 |
| `candidate_created` | 已创建待审批 | 到审批页人工确认 |

### 3.4 Canary 触发暂停

- 暂停只停止新分流，**不会自动回滚**生产版本。
- 配置中记录 `pausedReason` 与 `pausedAt`。
- 处理方式：分析健康指标 → 人工决定回滚或调整阈值后重新启用。

### 3.5 导入外部演化包

1. 通过校验接口读取摘要（agent 数、版本数、候选数、已脱敏样本数）。
2. 校验失败原因包括：schema 不匹配、schema 版本不支持、checksum 不一致、含敏感字段。
3. 导入内容**仅供人工参考**，不会激活版本或创建可批准候选。

## 4. 安全边界（必须保持）

- 不自动激活、回滚、提交、推送、合并、发布、删除。
- 治理配置、权限、预算、工作区边界不可被演化候选修改。
- 组合校验会阻断：绕过审批、自动提交/发布/删除、修改预算、跨工作区越权、读写凭据，以及自相矛盾的指令。
- 生产会话原文、密钥、附件、绝对路径、未审核工具输出不得进入样本、benchmark、导出包与报告。

## 5. 故障处理

| 现象 | 排查方向 |
|---|---|
| 评测无结果 | 渠道/模型是否显式启用；是否达到 3 条已脱敏样本与 1 条 held-out |
| 候选无法批准 | 父版本或内容 hash 是否已变化（需重新评测） |
| 建议不出现 | 样本阈值、冷却期、每日预算、是否存在待审批候选 |
| 回滚失败 | 目标是否为当前 active 版本；父版本 scope 是否一致 |
| 版本迁移后历史对不上 | 历史执行绑定冻结版本，属预期；不要在旧执行上重新解读 |

## 6. 当前限制（未实现）

- 无真实模型端到端自动化验收；评测链路需人工触发与观察。
- 无外部证据自动对账，无法证明生产质量变化。
- 健康告警推送、方差展示、时间窗并列对比与评测漂移告警尚未接入 UI。
- 跨员工迁移默认关闭，且不复制来源分数；迁移价值仍需目标员工自行评测证明。
- 全仓 `bun test` 仍受既有基线失败影响，不能作为发布门禁的通过证据。
- 治理配置的修改接口未绑定 UI，目前需通过 IPC 调用。
